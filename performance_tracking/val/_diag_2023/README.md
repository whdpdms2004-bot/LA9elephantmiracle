# fold 2023 예측 — **val 이 아니다. 진단용으로만 보존한다.**

`performance_tracking/README.md` 규칙 1 은 val 을 **2022 와 2024** 로 규정한다.
여기 파일들은 fold 2023 예측이고 **판정에 쓰지 않는다.**

## 왜 2023 을 쓰지 않는가 (2026-08-27 실측)

fold 2023 은 **학습이 전부 `game_type` 단절 이전(2019~2022)이고 검증이 단절 이후**다.
모든 멤버가 비슷하게 어긋나므로 최소제곱이 **공통 오차를 상쇄하는 큰 차분**을 찾고,
그 가중치는 전이되지 않는다.

```text
적합 도구                 가중치 cb/ft/mlp          eval2024
fit(2022 · R)            +0.722 +0.127 +0.162        877.8    <- 채택
fit(2023 · all)          +2.765 −2.209 −0.635       −444.2
fit(2023 · R)            +2.854 −2.328 +0.706        248.4
```

**부분군을 R 로 좁혀도 발산한다.** `analyze_members.py` 에 `BANNED_FIT_FOLDS = (2023,)`
로 못박았고 `--fit-fold 2023` 을 명시해도 거부한다.

## 그래도 남기는 이유

멤버가 **레짐 단절을 얼마나 견디는지**를 보여주는 유일한 자료다. 예를 들어

```text
             val2024        val2023        val2022
cb            881.8          228.2         2469.7
lgb63         706.1           48.8         2037.8
```

같은 폴드에서 멤버 서열이 유지되는지(cb > ft > lgb63) 확인하는 데 썼다.
새 멤버를 만들 때 참고 자료로만 본다.
