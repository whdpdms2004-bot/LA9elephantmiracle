## 0. 판단의 근거 — 왜 피처가 아니라 용량인가

현 챔피언 `sj_stdmlp` = Public **1,082.106**. 남은 레버의 기대값을 전이율로 환산하면:

| 레버 | val 이득 | 전이율 | **기대 Public** |
|---|---:|---:|---:|
| 항목 M (cntdev 3열) | +7.6 | 0.06 | **+0.5** |
| yn A3 (A_BOTH) | +3.9 | 0.06 | **+0.2** |
| 시드 3→8 (분산 축소) | +2.6 | ~1.0 | **+2.6** |
| **용량 재탐색 (depth·l2)** | ? | **0.88** | **한 칸당 +3 근처** |

**피처를 더 붙이는 일은 기대값이 +0.5 이하다.** 반면 용량은 08-28 에 `depth 5→6` 하나로
val +3.7 을 냈고 전이율이 0.88 이다. 그리고 **피처를 늘리면 용량 최적점이 움직인다** —
176열에서 depth 5→6 이 일어난 것이 바로 그 사례다. cntdev(+3)·A3(+3)를 붙여 182열이
되면 최적점을 다시 찾아야 한다.

**그래서 이 계획의 뼈대는 "피처를 고정한 뒤 용량을 다시 맞추는 것"이다.**
피처 추가는 용량 재탐색의 무대를 넓히는 수단이지 그 자체가 목적이 아니다.

시드 3→8 은 공짜에 가깝다. `S8_cb_base` 실측으로 val2024 900.0→**902.6**, 분포를 바꾸는
변경이 아니라 평균의 분산을 줄이는 것이라 전이율이 1.0 에 가깝다. **전 슬롯에 적용한다.**

### 건드리지 않는 것

- **팀 결합가중** `w_cw 0.4546 · w_sj 0.6433 · shift 0.003223` — 결합층 상수 전이율 ~0.
- **보정상수** — 평가 라벨로 다시 고르면 계기가 오염된다 (`01_calib_discrepancy.md`).
- **`model/sj/`·팀원 모듈** — 한 바이트도.

## 2. 1단계 — 용량 격자 (목표 1시간)

피처셋을 **176 + cntdev 3 = 179** 로 고정하고 depth·l2 를 다시 훑는다.
A3 는 여기 넣지 않는다 — 이유는 §5.

**도구는 `depth_raw.py` 를 쓴다.** 이 스크립트는 존재 이유가 바로 이것이다 — 문서 첫 줄이
"깊이 순위를 **오염되지 않은 계기**로 다시 매긴다" 이고, `run_arm.calib` 가 평가 폴드
라벨로 스케일을 고르는 오염(`01_calib_discrepancy.md` 와 같은 종류)을 피해 간다.

```bash
cd /c/Users/isj67/Desktop/LA9elephantmiracle/cowork/sj/sj_final/src

# (a) 먼저 현행 176열에서 depth 6 이 아직 최적인지 확인 — 코드 수정 0
python depth_raw.py --depths 5,6,7,8 --seeds 3

# (b) 179열(=cntdev 포함)에서 다시. depth_raw.py:92 한 줄을 고쳐야 한다:
#     E, en = A.build(X, names, season <= fold - 1, fold, ["id_freq"])
#   여기에 cntdev 3열을 더하는 경로를 run_arm.py 의 --extra 처리와 같게 붙인 뒤
python depth_raw.py --depths 6,7,8 --seeds 3
```

`--l2` 인자는 `depth_raw.py` 에 없다. l2 를 훑으려면 `run_arm.py:CB_P` 의 동결값을
직접 바꿔 arm 을 따로 돌려야 하므로 **시간이 남을 때만 한다.**

**판정**: val2024 와 val2022 가 **둘 다** 동결값(depth 6)보다 높은 depth 만 후보다.
한쪽만 오르면 버린다 — 2022 관문이 08-28 에 l2 하향을 막은 전례가 있다.

l2 는 depth 승자가 정해진 뒤에만 `{3000, 10000, 30000}` 로 한 번 더 훑는다. 시간이 없으면
**생략하고 10000 을 유지한다** (동결값이라 안전하다).

## 3. 2단계 — 승자 8시드 확정 + 관문 (목표 1시간)

```bash
python run_arm.py --name FINAL_cb --atoms id_freq --extra cntdev \
  --models cb --seeds 8 --folds 2024,2022,2023 --depth <승자> --l2 10000
python run_arm.py --name FINAL_mlp --atoms id_freq \
  --models mlp --seeds 8 --folds 2024,2022,2023
```

조립·판정은 `results/yn_a3/assemble.py` 를 arm 이름만 바꿔 재사용한다.

**4관문 (전부 통과해야 제출 후보)**
1. val2024 all ≥ 900
2. 동일 계기 BASE 대비 val2024 상승
3. 동일 계기 BASE 대비 val2022 상승
4. val2022 R · val2023 R 비하락

관문 1 은 **계기에 따라 갈린다**(배포보정 900.6 vs 무보정 925.2). 두 계기 모두 기록하고,
**배포보정 기준으로 판정**한다 — 실제 배포가 보정을 걸고 나가기 때문이다.

## 4. 3단계 — 배포 재굽기와 ZIP (목표 2시간)

```bash
# cb 재학습 (2019~2024 전체)
python build_final_cb.py --out _stage_final --atoms id_freq --extra cntdev \
  --depth <승자> --l2 10000 --seeds 8            # VRAM 미확보면 --cpu

# mlp — 챔피언 그대로면 재굽기 불필요. 시드만 8로 올릴 때만 실행
python build_final_mlp.py --out _stage_final --seeds 8

# zip
python build_submit_zip.py \
  --base ../../../performance_tracking/models/sj_stdmlp.zip \
  --cw _stage_final --out ../../../performance_tracking/models/sj_final_M.zip

python check_submit.py --zip ../../../performance_tracking/models/sj_final_M.zip
```

**ZIP 검증 — 하나라도 실패하면 제출하지 않는다**
- `check_submit.py` 주의 0건
- `script.py` smoke (실제 test.csv 로 1회)
- 행 독립성: `predict(1행)` vs `predict(전체)[0]` 최대절대차 `0.000e+00`
- 행순서·배치크기 불변
- 600초 제한 내
- `model/sj/`·팀원 모듈 md5 원본과 동일

ZIP 은 커밋하지 않는다. 절대경로·크기·SHA-256·엔트리 목록만 문서에 적는다.

## 5. 슬롯 3개 배분

Public 피드백이 즉시 오므로 **순차로 쓴다.**

| 슬롯 | 구성 | 기대 | 근거 |
|---|---|---|---|
| **1** | 챔피언 + 항목 M, **depth 6 동결**, 시드 8 | +3 근처 | M(+0.5) + 시드(+2.6). 용량 미변경이라 가장 안전 |
| **2** | 슬롯1 + **depth 격자 승자** | +3~+6 | 전이율 0.88 짜리 유일한 레버 |
| **3** | 슬롯1·2 결과를 보고 결정 | — | 아래 규칙 |

**슬롯 3 결정 규칙**
- 슬롯 2 가 슬롯 1 보다 **올랐으면** → 같은 방향으로 용량 한 칸 더 (격자 2등).
- 슬롯 2 가 **떨어졌으면** → 용량은 접고 슬롯 1 피처셋에 **A3 를 얹는다** (A_BOTH).
- 둘 다 챔피언(1082.106)보다 **낮으면** → 아무것도 더 내지 않는다. 챔피언이 최종본이다.

### A3 를 1·2 슬롯에서 뺀 이유

1. 기대 Public 이 **+0.2** 다. 용량(+3)의 1/15.
2. `build_final_mlp.py:167` 이 `["id_freq"]` 로 하드코딩돼 있다. 고칠 곳은 **한 줄**이라
   위험이 크지는 않지만, 마감 하루 전에 배포 경로를 건드리는 값이 +0.2 는 아니다.
3. 8시드 확인이 미완이고, 3시드 여유폭이 관문1 **0.6**·2023R **0.3** 밖에 안 된다.
4. A_CB 는 코드 수정 없이 되지만 관문 1·4 를 이미 탈락했다.

슬롯 3 에서 쓰게 되면 그때 `build_final_mlp.py` 를 패치한다.
