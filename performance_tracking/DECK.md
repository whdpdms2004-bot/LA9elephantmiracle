## 1. 문제와 지표

**과제** 투구 한 개가 제구에 성공할 확률을 `0~1` 실수로 예측한다.

**지표** Brier Skill Score — 기저율 대비 개선분

```
Score = 100000 × ( 1 − Brier / (r(1−r)) )        r = 그 부분군 실제 성공률
```

- **확률 문제다.** AUC 가 아니라 **보정(calibration)** 이 점수를 지배한다.
- 기저율로 나누므로 **부분군마다 척도가 다르다.** 이게 뒤에서 관문 문제를 만든다.

**데이터** 학습 1,475,092행 (2019~2024) · 검증 2024 253,507행 / 2022 247,472행

**규정 제약 3개** — 설계를 실제로 구속한 것들

| 제약 | 결과 |
|---|---|
| 미래 참조 금지 | 예측 시즌 이전 데이터만. TrackMan 이력도 동일 |
| **행 독립성** | `predict(1행) == predict(전체)[i]`. **투구수 누적 피처가 원천 봉쇄** |
| 학습 코드 제출 | 09.11 검증. `model/` 을 원본에서 재생성할 수 있어야 한다 |

> 말할 것: 행 독립성이 왜 중요한지 한 문장 — "부하비가 진짜 약점인데 못 쓴 이유가 이거다."

## 2. 최종 제출 구조

### 2.1 두 층

```
┌ 팀 결합층 ───────────────────────────────────────────┐
│  p = r + w_cw·(p_cw − r) + w_sj·(p_sj − r) − shift  │
│      w_cw 0.45461   w_sj 0.64333   shift 0.003223   │
└──────────┬───────────────────────┬──────────────────┘
           │                       │
   ┌───────▼────────┐      ┌───────▼────────┐
   │  cw 모듈        │      │  sj 모듈        │
   │  3멤버 스택     │      │  3WAY 모델      │
   │  ← 내가 개선    │      │  ← 한 바이트도  │
   │                │      │     안 건드림   │
   └────────────────┘      └────────────────┘
```

### 2.2 cw 모듈 — 세 멤버가 **서로 다른 표현**을 본다

```
p_cw = r + 0.7432·(p_cb − r) + 0.1598·(p_ft − r) + 0.1646·(p_mlp − r)
```

| 멤버 | 학습기 | **입력 표현** | 무엇을 보나 |
|---|---|---|---|
| **cb** | CatBoost RMSE · depth 6 · lr 0.02 × 3000 · `l2_leaf_reg` 10000 · 3시드 | **176열 원시값** | 트리 — **순서만** |
| `ft` | FT-Transformer · `d_token` 64 · 3층 8헤드 · drop 0.1 | 168열 **분위수 순위** | 토큰당 1열 |
| `mlp` | 잔차 MLP · width 384 · depth 3 · drop 0.3 · 3시드 | **352 = 176 z점수 + 176 결측마스크** | **크기 보존** |

**피처 176 = 168 + 8**

```
168 = 원본 72 + 시즌폼 8 + TrackMan 55 + 볼카운트 27 + 역할 5 + 결측표시 1
  8 = id_freq   (투수·타자·양팀 4개 ID × {log빈도, 미관측여부})
```

### 2.3 배포 순서 — 이 순서가 수치를 바꾼다

```
멤버별 예측 → apply_calibration(로짓 아핀 + 목표율 중심이동 + 클리핑) → 확률 공간에서 결합
```

로짓 아핀과 확률 결합은 **교환되지 않는다.** 원시 예측으로 적합한 가중과 다르다.
`mlp` 보정 상수는 원본과 같은 절차로 다시 뽑았다 —
`logit_scale 0.80`, `logit_center_C0 −0.061225`, `target_rate 0.474695`.

> 말할 것: 2.2 표의 "입력 표현" 열을 손으로 짚으면서 읽는다. 4장의 결론이 여기서 나온다.

## 4. 핵심 결정 넷

### D1 — `id_freq`: "학습에 없던 선수" 를 표시한다

**물음** 새 시즌에는 학습에 없던 투수가 등장한다. 모델이 그걸 아는가?

**한 것** ID 4종에 대해 `log(빈도)` 와 `미관측 여부` 2열씩, 총 8열.
**값 자체가 아니라 상황을 표시만 한다.**

**결과** cb 단독 val2024 881.8 → **902.8 (+21.0)**, val2022 +10.8 → Public **+1.33**

**왜 되는가** ID 를 카테고리로 넣으면 과적합한다. **빈도는 "이 예측을 얼마나 믿을지"** 를
말해줄 뿐 라벨 신호를 건드리지 않는다.

> **대조 실험이 이걸 확인해준다.** 같은 발상으로 `asof_*` 를 지운 사본을 20/40% 덧붙였더니
> Δ24 −3.9~−8.5 로 전부 기각이다. 이력을 지운 사본은 **이력이 없는데 라벨은 그 투수의
> 진짜 실력을 반영**해서 잡음을 학습한다. `id_freq` 는 **표시만 하고 학습 신호를 안 건드려서** 됐다.

### D2 — CatBoost `depth 5→6`: 조건부 재탐색 조항

**물음** 피처가 168 → 176 으로 바뀌었다. 하이퍼 최적점이 이동하지 않았을까?

**한 것** 계획서에 미리 달아둔 조건("입력 피처셋이 **실제로 바뀌면** 격자를 다시 판다")이
발동. 9설정 × 3짝시드 × 2폴드 = 54판, **16.4분**.

**★ 두 폴드가 정반대를 원한다**

|  | val2024 | val2022 |
|---|---|---|
| 원하는 방향 | 깊고 **약한** 규제 | 얕고 **강한** 규제 |

| 후보 | val2024 | val2022 | 판정 |
|---|---:|---:|---|
| **`d6` · `l2 10000` 유지** | **+4.2** | **+0.0** | **채택** |
| `d6_l3k` (규제 완화) | +8.9 | **−7.9** | 탈락 |
| `d7` / `d8` | 계속 상승 | **−1.6 / −10.7** | 탈락 |

**결정: 깊이만 올리고 규제는 그대로.**
val2024 만 봤으면 `d6_l3k` 를 골라 2022 를 −7.9 깎았을 것이다. **관문이 실제로 일했다.**

**Public +3.71 — 단일 최대 기여.**

### D3 — 표현 교체: `mlp` 이 왜 죽어 있었나

**물음** `mlp` 가중이 원시 계기에서 **정확히 0.00** 이다 (cb depth 5~8 전부). 왜?

**한 것** 전처리 4종 × `id_freq` 포함 여부를 교차.

| mlp 전처리 | 단독 val2024 | **가중** | 결합 Δ |
|---|---:|---:|---:|
| `q64:168` (현행) | 635.1 | **0.00** | +0.0 |
| `q64:176` (id_freq 만 추가) | 630.9 | **0.00** | +0.0 |
| `q256:176` (해상도 4배) | 635.4 | **0.00** | +0.0 |
| `gauss:176` (정규분포화) | 576.2 | **0.00** | +0.0 |
| **`std:176` (로버스트 z점수)** | **668.3** | **0.15** | **+12.3** |

**답 — 분위수-순위 변환은 순서만 남기고 크기를 버린다.**
트리도 순서만 쓴다. 그래서 **순위 MLP 는 cb 와 같은 정보를 다르게 계산할 뿐**이었다.
해상도를 4배로 올려도(q256), 정규분포로 바꿔도(gauss) 0 이다 —
문제는 해상도가 아니라 **크기를 버리는 것 자체**다.

> **★ `id_freq` 를 넣는 것만으로는 효과가 정확히 0 이었다(`q64:176`).**
> **바꿔야 했던 것은 피처가 아니라 표현이다.**

**교차 검증 하나 더** — `ft` 를 z점수로 바꾸면 단독은 두 폴드 다 최고인데(+22.0/+41.6)
**결합 이득이 0** 이다. `std_mlp` 이 이미 z점수를 담당해서다.
→ **표현 레버는 표현당 한 번이다.**

### D4 — 팀 가중을 건드리지 않기로 한 결정

**물음** cw 모듈이 좋아졌으니 `w_cw` 를 올려야 하지 않나?

**실측 두 번**

| 변경 | 하네스 예측 | Public 실측 |
|---|---:|---:|
| 합 1.098 → **1.143** (합 이탈) | −6.1 | **−6.7** ✅ 정확 |
| 합=1 안에서 `w_cw` 0.41 → 0.64 | +2.2 | **−0.03** ❌ 과대 |

**기전** `center_shift` 는 평균만 맞추고 **합≠1 이 만드는 분산 팽창을 못 되돌린다.**
반면 합 제약 안에서의 `w` 위치는 val 이 보여준 것보다 **실제로 훨씬 평평하다** —
val 고원 폭 0.8 이 테스트에서 0.026 으로 눌린다.

**결정: 팀 가중은 인계받은 값 그대로 둔다.**
`w_cw 0.45461 / w_sj 0.64333 / shift 0.003223` — **한 번도 안 바꿨다.**

> **결합층에서는 잃을 수는 있어도 벌 수는 없다.**

**단 cw *내부* 가중은 반대다.** 팀 층 `center_shift` 가 스케일을 흡수하므로
합 제약이 오히려 해롭다 (합=1 정규화가 val2022 **−8.1**). 그래서 내부는 합 1.0676 자유.

> 말할 것: D4 는 "안 한 결정"이다. 안 한 것도 결정이라고 말한다.

## 5. 멤버를 어떻게 골랐나

### 5.1 비음수·합=1 제약으로 적합하면 답이 나온다

| 조합 | 정방향 | 역방향 | 적합 가중 |
|---|---:|---:|---|
| **`cw + sj3way`** | 727.0 | 1055.5 | [0.70, 0.30] |
| `+ hw` | 727.0 | 1055.5 | [0.70, 0.30, **0.00**] |
| `+ yn` | 727.0 | 1052.1 | [0.70, 0.30, **0.00**] |

**`hw`·`yn` 에 정확히 0 이 붙는다** — 개별 모델이 약해서가 아니라 `sj3way` 와의
상관 **0.95+** 로 인한 **구조적 중복**이다. 챔피언 작성자의 판단이 독립 재현됐다.

### 5.2 ★ 비교 대상을 틀리면 결론이 뒤집힌다

`yn` 을 **내 cw 스택**(ρ 0.8949)과 비교하면 탈상관 자산으로 보이고 2멤버 자체적합 +18.2 다.
그러나 **실제 결합 상대는 `sj3way`** 이고 그쪽과는 **ρ 0.9572** 다.

> **편입 검토는 실제 결합 상대로 해야 한다.**

### 5.3 그런데 ρ 가 낮다고 좋은 것도 아니다

4번째 멤버 후보 넷 중 **ρ 가 가장 낮은** `lin_std176`(0.751)이 가중 **−0.014** 로 사실상 0 이고,
채택된 `std_mlp` 은 탈락한 `q64_mlp` 보다 ρ 가 **더 높다**(0.8924 vs 0.8752).

**결합 유용성을 예측하는 것은 ρ 가 아니라
"다른 멤버가 구조적으로 접근할 수 없는 정보를 담은 표현" 이다.**

## 6. 검증 방법론 — 실제 산출물

### 6.1 계기 오염 두 건을 잡았다

| # | 무엇 | 영향 |
|---|---|---|
| 1 | `run_arm.calib` 이 **평가 폴드 라벨로** 로짓을 재중심화 | 같은 모델이 **저장 904.1 / 원시 851.3** |
| 2 | 팀원 공유분이 `eval_set` + `use_best_model` 로 **검증 라벨을 조기 종료에** | val2024 808.9 → **720.6** |

**#1 때문에 "채택" 이라 불렀던 결론 두 개가 뒤집혔다.**
`cb_f_only`("3.42σ 채택안")와 "정확도와 탈상관은 같은 축(r=+0.994)" 이라는 법칙 자체.

### 6.2 자체적합은 반드시 부풀린다

way 계열평균이 **자체적합 +9.6 → 정직 전이 +1.2.** 8.4 가 거품이었다.
→ **적합 fold 와 평가 fold 를 반드시 분리한다.**

### 6.3 오차 상관은 쓸 수 없다

예측 분산이 라벨 분산의 **0.86%** 라 오차가 사실상 `−y` 항이고 **모든 모델의 오차 ρ ≈ 1**
(cb·ft 예측 ρ 0.9313 vs 오차 ρ 0.9994). 같은 이유로 `huber(α=0.9)` 가
squared error 와 **비트 단위로 동일**하게 나왔다.

### 6.4 부분군 진단 — 어디서 잃는지의 좌표

15축 × 구간. `train.csv` 에 경기 ID 가 없어 **`game_uid` 를 복원**했다
(시즌당 796~824경기 · 경기당 중앙 300구 · 등판당 중앙 19구).

**최대 약점은 볼카운트다.** `0-2` 가 AUC **0.5323 / 0.5316** (전체 0.5488 / 0.5541),
두 시즌 값이 거의 같다. `bias` −0.001 → **치우침이 아니라 변별력 문제**.
예측 표준편차도 그 구간에서만 **15~22% 좁아진다** — **모델이 신호 없음을 알고 수축한다.**

**통념과 반대로 나온 것**: 경기 중요도(li)는 격차가 없다. 6구간 중 4구간 부호 반전,
`li≥2.00` 은 오히려 두 시즌 다 평균 위.

## 7. ★ 이 프로젝트의 중심 결과 — 전이율은 변경 종류마다 다르다

| 변경 종류 | val Δ | Public Δ | 전이율 |
