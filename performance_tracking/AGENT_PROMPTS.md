# 팀원 에이전트용 프롬프트

> `performance_tracking/` 을 pull 한 뒤 각자 자기 Claude Code 세션에 붙여넣는다.
> **[공통] 블록 + 자기 이름 블록** 두 개를 이어서 한 번에 넣는다.

`performance_tracking/` 에는 문서가 10개 넘게 있는데 **대부분은 sj 트랙의 내부 실험
기록**이다. 하네스가 달라 숫자를 옮기면 틀린다. 그래서 아래 프롬프트는 **읽을 것보다
읽지 말 것을 먼저 지정한다.** 이 부분을 빼고 주면 에이전트가 `PROGRESS_workflow.md`
같은 걸 물고 와서 엉뚱한 기준선으로 작업한다.

LG Aimers 9기 Phase 2 (투구 제구 성공 확률 예측) 팀 LA9 저장소다.

## 읽을 것 — 이 순서로, 이것만
1. performance_tracking/TEAM_BRIEF.md     전체. 내가 뭘 해야 하는지가 여기 있다
2. performance_tracking/README.md         §0 규칙 4개(규칙 1 은 08-28 개정됨) · §2 val 규격 · §3 채점 · §5 등록 절차
3. cowork/RULES.md                        §1 일정 · §2 추론 독립성 · §5 zip 규격

## 읽지 말 것 (내가 따로 시키기 전에는)
performance_tracking/ 의 나머지 문서 — PROGRESS_workflow.md · PLAN_next.md ·
SUBMISSIONS_AND_ENSEMBLE.md · HANDOFF_sj_final.md · COLLAB_final_submissions.md ·
models/sj_*.md · results.csv 의 `[실험기록]` 으로 시작하는 행 — 은 전부 sj 트랙의
내부 실험 기록이다. 계기와 하네스가 달라서 거기 숫자를 내 작업의 기준선으로 쓰면
틀린 결론이 나온다. 필요하다고 판단되면 읽기 전에 나한테 먼저 물어라.

## 이 저장소에서 절대 어기면 안 되는 것 3개
1. 미래를 보지 않는다. val2024 는 2023 이전만, val2023 은 2022 이전만,
   val2022 는 2021 이전만 학습한다. TrackMan 이력도 예측 시즌 이전 것만 쓴다.
2. 평가 시즌의 라벨이 학습 절차 어디에도 닿으면 안 된다 — 조기 종료(eval_set /
   use_best_model), 후처리 보정(calibration), 임계값 선택 전부 포함이다.
   팀이 이 함정을 이미 두 번 밟았고 그때마다 결론이 뒤집혔다.
3. test 의 다른 행을 보지 않는다. predict(단독 행) == predict(전체)[i] 가 성립해야 한다.

## 작업 방식
- cowork/<내 이니셜>/ 안은 자유, 나머지 경로는 건드리지 말고 PR 로만 올린다.
- 브랜치 <이니셜>/<짧은설명>, 커밋 `[<이니셜>] <type>: <설명>`
  (type = feat/fix/exp/doc/chore).
- 작업이 끝나면 cowork/task.jsonl 에 JSON 한 줄을 `>>` 로 append 한다.
  기존 줄은 고치지 않는다 (JSON 배열이 아니라 JSONL 이다).
- 데이터는 저장소에 없다. data/train.csv 와 data/trackman_history.csv 가
  로컬에 있는지 먼저 확인하고, 없으면 대회 페이지에서 받으라고 알려라.

## 보고 규칙
- 측정하지 않은 값을 결과처럼 쓰지 마라. 모르면 "미측정" 이라고 적는다.
- 숫자를 보고할 때는 **어떤 계기로 쟀는지**를 같이 적는다. 같은 모델이 계기에 따라
  904.1 / 851.3 으로 갈린 적이 있다.
- 작업이 끝나면 "무엇을 만들었고 / 어디에 뒀고 / 어떻게 검증했고 / 무엇이 미검증인지"
  네 줄로 요약한다.

performance_tracking/val/hw_v12_2022.csv   (<=2021 학습)

- 컬럼 2개, 헤더 필수. row_id 는 data/train.csv 의 문자열 그대로. 정렬 순서 무관.
- pred 는 최종 control_success 확률 하나. way 확률이나 로짓을 넣지 않는다.
- 각 시즌의 control_success 비결측 행을 전부 담는다. 결측·중복·누락은 오류다.

## 만드는 법
performance_tracking/models/hw_v12/train_best_model_v12.py 의 학습 시즌만 바꿔
두 번 돌린다 (`<=2021` -> 2022 예측, `<=2022` -> 2023 예측).
**하이퍼파라미터와 피처는 그대로 둔다** — val2024 와 비교가 되어야 하므로 바뀌면 안 된다.

## 왜 2022·2023 은 R 만 보는가 (규칙 1, 2026-08-28 개정)
2022 의 F 기저율은 0.7087, R 은 0.5037 로 0.2 벌어져 있다 (2024 는 F 0.4593 · R 0.4897
로 거의 같다). BSS 가 기저율로 정규화되므로 2022 를 all 로 재면 점수의 상당 부분이
성능이 아니라 game_type 구성을 재게 된다.
**주 판정은 2024 all(R+F), 관문은 2022 R 과 2023 R 이다.**
예측 파일 자체는 R/F 구분 없이 그 시즌 전체 행을 담는다 — 부분군 분리는 도구가 한다.

## ★ 반드시 피할 것 — 내가 이미 한 번 밟은 함정이다
models/hw_v12/build_val2024_pred_v12.py 가 `eval_set=(x_val, y_val)` +
`use_best_model=True` 로 **검증 라벨을 조기 종료에 썼다.** 그래서 sj 가 정직본을
다시 만들어야 했고 점수가 val2024 808.9 -> 720.6 으로 내려갔다.
이번엔 반복하지 마라. early stopping 이 필요하면 `<=2021` 안에서 뒷부분을 떼어 쓴다.
평가 시즌(2022) 행은 학습 루프 어디에도 들어가면 안 된다.

## 검증 (내가 돌려서 통과시킨 다음에 보고한다)
python performance_tracking/tools/score_val.py hw_v12 --baseline cw_v17_base

- 각 시즌 행 수가 그 시즌 비결측 행 수와 일치하는지
- pred 평균이 0.35~0.65 안인지 (밖이면 도구가 거부한다)
- 오류 없이 all / R / F / 월블록 점수가 나오는지

보고할 때 **sj 가 재계산한 720.6 계열의 숫자와 내 자체보고 808.9 를 섞지 마라.**
서로 다른 계기의 값이라 섞으면 비교가 무의미해진다.
