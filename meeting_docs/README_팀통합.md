# 팀 통합 문서 — KBO 투구 제구 성공 확률 예측

**5개의 독립 라인을 대조하고, 앞으로의 방향을 정한 문서**

---

## 이 문서를 만든 이유

우리 팀은 5명이 각자 다른 방식으로 이 문제를 풀었습니다. 그 결과 **같은 데이터에서
독립적으로 얻은 다섯 벌의 증거**가 생겼습니다. 이건 흔치 않은 자산입니다.

한 사람이 "이 피처가 좋다"고 하면 우연일 수 있지만, **네 명이 서로 모르는 채로 같은
결론에 도달했다면 그건 사실에 가깝습니다.** 반대로 한 명만 성공한 것은 그 사람의
구현 세부사항 덕일 수 있으니 조건을 따져봐야 합니다.

이 문서는 다섯 문서를 대조해서:

1. **전원이 확인한 것** — 더 검증할 필요 없음, 그대로 씁니다
2. **의견이 갈린 것** — 왜 갈렸는지 따져서 조건을 붙입니다
3. **전원이 실패한 것** — 팀 차원에서 종결합니다
4. **아무도 안 해본 것** — 여기에 남은 점수가 있습니다

로 정리하고, 마지막에 **가장 큰 미개척 기회 하나**를 제안합니다.

## 1. 전원이 독립적으로 확인한 것 — 확정 사실

### 1-1. 투수 × 타자 좌우(플래툰)가 가장 강한 신규 신호

**5명 중 4명이 독립적으로 발견했습니다.**

| 누가 | 어떻게 불렀나 | 결과 |
|---|---|---|
| README(무명) | `asof_pitcher_vs_hand_success_rate_smoothed` | val 755.7 → **816~819**. "프로젝트 전체에서 가장 큰 단일 개선" |
| 찬우 | `enc_platoon_split` | LB **+32.5점** (841 → 873.5 상당) |
| 예나 | `hand_matchup`, `same_hand` | 최종 68피처에 포함 |
| 승주 | reverse residual의 `pitcher_hand × batter_hand` 축 | 시스템 핵심 구성요소 |

**왜 이게 큰가.** 대회가 제공한 `asof_pitcher_success_rate`에는 **좌우 구분이 없습니다.**
좌타 상대 58.4% / 우타 상대 43.2%인 투수(#23637)도 평균 0.50 하나로 뭉개집니다.
15%포인트짜리 정보가 통째로 사라진 겁니다.

승주 문서의 좌우 조합별 전체 성공률도 이를 뒷받침합니다.

| 투수손 × 타자손 | n | 성공률 |
|---|---:|---:|
| 좌 × 좌 | 170,292 | 0.4909 |
| 좌 × 우 | 211,059 | **0.5375** |
| 우 × 좌 | 525,455 | 0.5307 |
| 우 × 우 | 568,286 | 0.5221 |

**전역 효과만 4.7%포인트**이고, 투수 개인별 편차는 훨씬 큽니다.

**팀 표준 구현:**
```
스플릿 = EB(투수의 해당 좌우 타자 상대 성공률) − EB(투수의 전체 성공률)
EB(x)  = (성공수 + K × 리그평균) / (표본수 + K)
```
주효과를 빼서 **레벨과 무관한 스플릿만** 남기는 게 핵심입니다. 주효과는 `asof_*`가 이미
잡고 있어서, 안 빼면 중복입니다(찬우 실험: 투수 주효과 단독 기여 = 정확히 0.0).

K값은 사람마다 다릅니다: README(무명) K=20, 예나 K=200, 찬우 K=300, 승주 K=200.
**K=100~300 구간에서 큰 차이가 없었으니 200으로 통일**하기를 제안합니다.

### 1-2. 2023 시즌은 다른 세계다

**전원 일치.** 어떤 모델을 써도 2023 검증이 무너집니다.

| 누가 | 2023 관측 |
|---|---|
| 정희원 | anchor BSS **11.64** (2022는 2282.07) |
| 승주 | "거의 null Brier 수준", 2019→2024 성공률 −7.86%p 중 2023이 −2.90%p |
| README(무명) | "거의 모든 실험에서 지속적으로 약한 검증 폴드" |
| 찬우 | 오라클 보정을 해도 **−1340점** |

**찬우 라인에서 원인을 특정했습니다.** 예측 상위 10% 구간만 완전히 뒤집혔고,
그 구간은 **표본이 적은 투수들**이었습니다.

| 십분위 | 1 | … | 9 | **10** |
|---|---|---|---|---|
| 예측 | .435 | … | .577 | **.689** |
| 실제 | .446 | … | .552 | **.477** |
| 누적 투구수 중앙값 | 2,504 | … | 4,607 | **1,345** |

1~9분위는 멀쩡합니다. 과거 성적이 좋았던 저표본 투수를 모델이 과신했고, 규칙이 바뀌자
무너진 겁니다. ABS(자동 볼판정) 도입 시기와 겹칩니다.

**팀 규칙:**
- **2024 하나만 보고 피처를 채택하지 않는다.** 최소 2022 + 2024, 가능하면 2023 포함
- 저표본 대상에는 반드시 EB 축소를 적용한다
- 극단 예측값에 상·하한(cap)을 두는 것을 고려한다 (찬우 실측: 정상 연도 10점 손해, 레짐 변화 시 800점 방어)

### 1-3. 선수 ID를 범주형·임베딩으로 쓰는 건 실패한다

**5명 전원이 시도했고 5명 전원이 기각했습니다.**

| 누가 | 시도 | 결과 |
|---|---|---|
| 예나 | pitcher_id + batter_id 범주형 | **36개 조합 전부 악화** |
| 정희원 | pitcher SVD 임베딩(k=4) | 2024 delta **−41.48** |
| 정희원 | pitcher-batter pair 임베딩 | 설계 단계 기각 (OOV 48.84%) |
| 찬우 | ID 원-핫 + L2 로지스틱 | AUC **0.5166** < asof 단독 0.5342 |
| 승주 | TabM에 raw ID 임베딩(T2) | temporal overfit 확인, 제외 |
| README(무명) | 뉴럴 임베딩 | 스모크 테스트 전부 채택 기준 미달 |

**왜 실패하는가 — 이유가 명확합니다.**

`asof_pitcher_success_rate`는 **정답(제구 성공 여부) 자체로 만든** 투수 기량 측정치이고,
**평가 시즌 진행분까지 실시간으로 반영**됩니다. 정적인 ID 임베딩은 과거에 고정돼 있어서
낄 자리가 없습니다.

여기에 승주 문서가 결정타를 더합니다: **다음 시즌 신규 투수 비율이 24.3~33.1%**입니다.
학습 때 본 적 없는 선수가 1/4~1/3이면 임베딩은 구조적으로 불리합니다.

> **결론: 이 방향은 팀 차원에서 종결합니다.** GPU가 평가 서버에 있다고 해서 딥러닝을
> 의심할 필요가 없습니다. 임베딩이 줄 수 있는 건 주효과인데 그건 이미 포화 상태입니다.

### 1-4. TrackMan 물리 데이터는 효과가 없다

**이게 팀에서 가장 많은 시간을 쓴 방향이고, 가장 확실하게 실패한 방향입니다.**

| 누가 | 시도 | 결과 |
|---|---|---|
| 예나 | **5차례 이상 독립 시도** (리그집계 / 구종믹스 / 8축 임베딩 / 물리편차 / 구위반복성) | **전부 기각.** 8축 임베딩은 5시드+Bonferroni 재검증으로 1차 결론 전부 철회 |
| 정희원 | tm_pred_8 (aux 모델 8개) | 검증 **3/3 개선**했는데 실LB **797 → 760.47 (−36.53)** |
| 찬우 | 매칭 578명 성공 후 물리 25피처 | AUC 0.5407 → 0.5413. 시드 대조군과 구분 불가 |
| 승주 | 직접 embedding / 대규모 injection | "검증 이득 없었다" |
| README(무명) | 8개 전부 → 실패, 2개만 선별 | **최종 검증 미완료** |

**매칭 자체는 여러 명이 성공했습니다.**

| 누가 | 방법 | 성과 |
|---|---|---|
| 찬우 | 경기 복원 → 팀 매핑 → 하프이닝 벡터 → 단독 투수 하프이닝 | 578명 1:1, 좌우손 **576/578 일치** |
| README(무명) | 연속 투구 시퀀스 fingerprint | unique match 85.4%, HIGH-confidence 커버리지 87.1% |
| 예나 | (582명 매핑 보유) | `pitcher_id_map.csv` |

**즉 "연결은 되는데 쓸모가 없다"가 팀의 공통 결론입니다.**

**이유:** `asof_pitcher_success_rate`가 이미 타깃 기반 기량 측정치라, 릴리스포인트 산포
같은 **물리적 대리지표**가 더할 정보가 없습니다.

**그리고 정희원 라인이 결정적 증거를 줍니다** — 검증에서 3/3 개선했는데 실제
리더보드에서 36점 하락했습니다. 검증에서 좋아 보여도 믿으면 안 되는 대표 사례입니다.

> **결론: TrackMan 물리 피처는 종결합니다.** 매핑 결과물(`pitcher_id_map.csv`)은
> Phase 3용으로 보관하되, Phase 2에서 더 시도하지 않습니다.
> **단, 예나 문서의 마지막 제안 — "정적 요약통계가 아니라 유사투수 prior로 재시도" —
> 는 아직 아무도 안 해봤습니다.** 우선순위는 낮지만 성격이 다른 시도입니다.

### 1-5. 검증 개선은 절반만 리더보드에 전이된다

**전원이 데었습니다.**

| 누가 | 검증 | 실제 LB |
|---|---|---|
| 정희원 tm_pred_8 | 3/3 개선 | **−36.53** |
| 정희원 v6 | 2024 +11.12 | **−16.97** |
| 예나 reverse_x_batter_favor | 3구간×3시드 전부 통과 | **−4.04** |
| 찬우 v6 | +14.4% | **−5.0%** |
| 찬우 플래툰 | +85 (단일모델) | +32.5 (**40% 전이**) |
| 승주 Cat V1 vs XGB V1 | Cat 우위 | Public은 **XGB 우위** |

**하지만 예외가 있습니다.**

| 누가 | 무엇 | 전이율 |
|---|---|---|
| **승주 submit_023** | residual 적층 체인 | **90.5%** |
| 예나 | LightGBM → +CatBoost 50:50 앙상블 | LB **+151.35** |

**패턴이 보입니다.**

| 변경 종류 | 전이 |
|---|---|
| 새 피처 추가 | **잘 안 됨** (40% 이하, 부호 반전도 있음) |
| 앙상블 / 배깅 / residual 적층 / 캘리브레이션 | **잘 됨** (90% 이상) |

정희원 문서가 이걸 한 줄로 정리했습니다.

> "하이퍼파라미터/앙상블처럼 **새 정보를 추가하지 않는** 변경이 지금까지 가장 안전했음"

**왜 그런가.** 새 피처는 "그 신호가 2025년에도 유효한가"라는 도박입니다. 반면 앙상블은
**이미 검증된 모델들의 분산을 줄이는 것**이라 새로운 가정이 들어가지 않습니다.

| 누가 | 사례 |
|---|---|

### 1-7. sklearn pickle을 제출에 쓰면 안 된다

**세 명이 독립적으로 같은 위험을 인지했습니다.**

| 누가 | 대응 |
|---|---|
| 예나 | HistGB를 **성능이 아니라 직렬화 안전성 때문에** 기각 (Brier로는 2위였음) |
| 예나 | Isotonic을 pickle 대신 **좌표 배열 JSON + `np.interp()`** 로 재현 |
| 찬우 | 트리를 **순수 numpy 배열로 export**, sklearn을 import조차 안 함 |
| 승주/README | LightGBM `booster.save_model()`, CatBoost `.cbm` 네이티브 포맷 |

로컬과 평가 서버의 sklearn 버전이 다르면(1.6.1 vs 1.8.0) pickle이 깨질 수 있고,
**제출한 뒤에야 알게 되며 일일 제출 횟수를 까먹습니다.**

**팀 표준: 네이티브 포맷만 사용.** LightGBM은 `save_model`, CatBoost는 `.cbm`,
sklearn 계열은 numpy 배열 export 또는 아예 사용 금지.

## 2. 의견이 갈린 것 — 조건을 따져야 함

### 2-1. 캘리브레이션 (베이스율 보정)

| 누가 | 결과 |
|---|---|
| 찬우 | 검증 388 → 529 (**+141**). 첫 제출 549 → 804의 핵심 |
| 승주 | submit_023에 2025 offset 적용 → Public **+21.3** |
| 예나 | isotonic 보정 채택 (개선 확인) |
| **정희원** | **로짓 절편 보정 + shrinkage → 2022/2023/2024 전부 악화, 기각** |

**왜 정희원만 실패했나.** 문서를 보면 `r_hat = 시즌별 base rate 선형외삽`을 썼습니다.
찬우 라인의 백테스트 결과가 이 차이를 설명합니다.

| 외삽 규칙 | 2024 추정 | 실제 .4861 |
|---|---|---|
| 3년 선형회귀 | .4877 | +.0016 |
| **감쇠 외삽 (λ=0.33~0.5)** | **.4815~.4855** | **−.0006~+.0046** |
| 직전 시즌 그대로 | .5000 | +.0139 |

선형회귀와 감쇠 외삽은 2024에서 비슷하지만, **2022·2023 같은 해에는 크게 갈립니다.**
정희원 라인이 2022/2023에서 악화된 건 외삽 규칙 자체가 그 해에 안 맞았을 가능성이 큽니다.

**그리고 더 중요한 구조적 이유가 있습니다.** 찬우 실험에서:

> `season`을 피처로 **남겨두면** 트리가 마지막 연도 구간으로 예측 수준을 자동으로 맞춰줍니다.
> 빼면 347 → −48로 폭락합니다.

즉 **모델이 이미 `season`으로 부분 보정을 하고 있으면 추가 보정의 이득이 작거나 마이너스**가
될 수 있습니다. 정희원 anchor는 원본 47컬럼(= `season` 포함)을 그대로 쓰므로 이미 보정이
들어가 있었을 수 있습니다.

**결론: 캘리브레이션은 조건부로 유효합니다.**
- `season`을 피처로 쓰고 있다면 → 추가 보정 이득이 작을 수 있음. 반드시 검증 후 적용
- 감쇠 외삽(λ≈0.3~0.5)이 선형회귀보다 안정적
- **적용 전에 "우리 모델의 예측 평균이 지금 몇인가"부터 확인할 것**

**벌점 크기는 반드시 알아둬야 합니다.**

```
Score 손실 = 100000 × (예측평균 − 실제평균)² / [r(1−r)] ≈ 401,000 × 오차²
```

| 평균 오차 | 잃는 점수 |
|---|---|
| 0.010 | 40 |
| 0.020 | 160 |
| 0.030 | **361** |

### 2-2. 앙상블이 단일 모델보다 나은가

| 누가 | 결과 |
|---|---|
| 예나 | LightGBM 단독 748.41 → +CatBoost 50:50 **899.76 (+151.35)** |
| 찬우 | 단일 평균 524.8 → 4개 배깅 **587.1 (+62)** |
| 승주 | residual 적층으로 895 → **916.7** |
| **README(무명)** | **CatBoost 단독 755.7 > 3모델 앙상블 671.5** ← 반례 |

**반례를 뜯어보면 조건이 다릅니다.** README(무명)의 앙상블은 **LightGBM + XGBoost +
CatBoost 단순평균**이었고, XGBoost가 517.3으로 압도적으로 나빴습니다.
**약한 모델을 같은 가중치로 섞으면 당연히 손해입니다.**

예나는 XGBoost를 빼고 **LightGBM + CatBoost만** 50:50으로 섞어서 +151점을 얻었습니다.

**결론: 앙상블은 유효하되, 두 조건이 필요합니다.**
1. **성능이 비슷한 모델끼리** 섞는다 (약한 모델을 같은 가중치로 넣지 않는다)
2. **가중치를 개수가 아니라 계열 단위로** 준다 (예나: `0.5×mean(LGB 20개) + 0.5×mean(Cat 10개)`)

### 2-3. 어떤 알고리즘이 최선인가

| 누가 | 1위 |
|---|---|
| 예나 (단일시드 Brier) | CatBoost 0.248056 > LightGBM 0.248104 > HistGB 0.248158 |

> **서로 다른 알고리즘을 여러 개 만들어 섞는 것**이 이득입니다(5부).

### 3-1. 예측할 수 있는 것이 거의 없다

## 5. 앞으로의 방향 — 가장 큰 기회는 "합치는 것"

### 5-1. 왜 이게 1순위인가

찬우 라인에서 결정적인 계산이 나왔습니다. **앙상블의 이득은 개별 성능이 아니라
모델 간 상관에 의해 결정됩니다.**

같은 사람이 만든 두 모델(897점, 852점)은 상관 0.9616이라 섞어도 **+4점**이었습니다.
반면 성능이 56점 낮은 구버전(841점)은 상관 0.9296이라 섞으니 **+21점**이었습니다.

```
상관 0.93 → 918점
상관 0.85 → 957점
상관 0.70 → 1041점
```

**우리 다섯 명의 모델은 서로 훨씬 덜 닮았습니다.**

| | 알고리즘 | 피처 | 구조 |
|---|---|---|---|
| 찬우 | HistGB 6~31리프 | 68~72 | 배깅 + 로짓 보정 |
| 승주 | CatBoost+XGB+TabM | 209~211 | residual 적층 |
| 예나 | LightGBM+CatBoost | 68 | 30시드 배깅 + isotonic |
| README | CatBoost 단독 | 60 | 네이티브 범주형 |
| 정희원 | CatBoost 단독 | 53 | anchor only |

**알고리즘도, 피처 수도, 구조도 전부 다릅니다.** 상관이 0.80~0.85일 가능성이 높습니다.

### 5-2. 예상 점수

| 조합 | ρ=0.90 | ρ=0.85 | ρ=0.80 | ρ=0.75 |
|---|---|---|---|---|
| 찬우+승주 | 969 | 995 | 1023 | 1052 |
| **찬우+승주+예나** | 981 | **1017** | **1056** | **1098** |
| +정희원 | 987 | 1018 | 1057 | 1102 |

**상관이 0.85 이하면 통과 추정선 1000점을 넘습니다.**

### 5-3. 어떻게 하는가 — 정답 없이 최적 가중치를 계산한다

예측을 베이스율 편차로 쓰면 `d = p − r`, Brier가 세 조각으로 분해됩니다.

```
BSS = (2A − V) / U       A = 평균[d(y−r)],  V = 평균[d²],  U = r(1−r)
```

| 기호 | 뜻 | **정답이 필요한가** |
|---|---|---|
| `U` | 문제 난이도 | 아니오 |
| `V` | 예측이 얼마나 퍼져 있나 | **아니오 — 예측만으로 계산** |
| `A` | 예측이 정답과 얼마나 같이 움직이나 | 리더보드 점수에서 **역산** |

```
A = ( BSS × U + V ) / 2          ← BSS는 각자의 Public 점수
w* = M⁻¹A                        ← M[i][j] = 평균[dᵢdⱼ], 예측만으로 계산
```

**즉 각자 제출했던 예측 CSV와 그때 받은 Public 점수만 모으면, 재학습 없이 최적 가중치가
닫힌 형태로 나옵니다.**

### 5-4. 실행 절차

**1단계 — 예측 수집 (반나절)**
각자 자기 최고점 제출물의 `output/submission.csv`를 공유합니다.
같은 `row_id` 순서로 정렬하면 상관 계산 준비 끝입니다.

**2단계 — 상관 확인 (10분)**
```python
D = np.column_stack([p_i - r for p_i in preds])   # r = 0.4735 (또는 각자 목표값)
M = D.T @ D / len(D)
rho = M / np.sqrt(np.outer(np.diag(M), np.diag(M)))
```
**이 표가 나오는 순간 결합 이득이 얼마인지 바로 압니다.** 0.9 이상이면 이득이 작고,
0.85 이하면 큽니다.

**3단계 — 가중치 계산 (10분)**
```python
A = np.array([(bss_i * U + M[i,i]) / 2 for i, bss_i in enumerate(bss_list)])
w = np.linalg.solve(M, A)
expected = float(A @ np.linalg.solve(M, A)) / U * 1e5
```

**4단계 — 견고성 확인**
`V`를 ±15% 흔들어 보고, 가중치를 ±0.1 흔들어 봅니다. 찬우 라인 경험상 이 구간에서
점수가 평평하면 안심해도 됩니다.

**5단계 — 제출물 통합**
가장 까다로운 부분입니다. 각자의 `script.py`를 하나로 합치되, **각 계열이 자기 전처리와
자기 캘리브레이션을 그대로 유지**한 뒤 마지막에 확률을 가중 합산합니다.

```
p = r + Σ wᵢ (pᵢ − r)
```

추론 시간을 확인하세요. 찬우 2계열 51초, 승주 시스템은 더 무거울 수 있습니다.
**제한 10분** 안에 들어와야 합니다.

### 5-5. 주의할 점

**(가) 각자의 `target_rate`가 다르면 먼저 통일해야 합니다.**
승주는 0.4792를 겨냥했고, 찬우는 0.47353을 썼습니다. 결합 전에 **하나로 맞춰야**
포물선 손실이 중복되지 않습니다.

**(나) 약한 모델을 억지로 넣지 마세요.**
`w* = M⁻¹A`가 알아서 작은 가중치(또는 음수)를 줍니다. 그 결과를 존중하세요.
정희원 라인(797점)은 가중치가 작게 나올 가능성이 높지만, **상관이 낮으면 여전히 기여합니다.**

**(다) 제출 횟수를 아끼세요.**
결합은 한 번만 제출해도 검증됩니다. 여러 조합을 다 내보지 마세요.

## 6. 2순위 이하 — 남은 개척지

### 6-1. 미검증인 채로 남은 것: 트리 깊이

찬우 라인에서 **두 연도 모두 노이즈를 넘은 유일한 하이퍼파라미터 변경**인데,
다른 변경과 묶여서 나가는 바람에 단독 검증을 못 했습니다.

| max_leaf_nodes | val 2024 | val 2022 |
|---|---|---|
| 63 | 519.7 | — |
| 31 | 627.8 | 2229.0 |
| **6** | **685.6** | **2266.0** |

**"신호가 극도로 약한 문제에서는 얕고 강하게 규제한 트리가 유리하다"**는 가설입니다.
승주 문서의 "XGBoost는 18~24 leaves 부근이 안정적, 무작정 큰 모델은 overfit"과 방향이 같습니다.
**하나만 바꿔서 검증해볼 가치가 있습니다.**

### 6-2. 각자 안 해본 것 교차 적용

| 아이디어 | 누가 갖고 있나 | 누가 안 해봤나 |
|---|---|---|
| isotonic 보정 | 예나 | 찬우, 승주, 정희원 |
| residual 적층 구조 | 승주 | 나머지 전원 |
| 로짓 축소 계수 튜닝 | 찬우 | 나머지 전원 |
| 다중시드 배깅(20~30) | 예나, 승주 | 정희원, README |
| beta calibration | 승주 | 나머지 전원 |

**서로의 기법을 한 개씩 가져다 붙이는 게, 새 피처를 찾는 것보다 기대값이 높습니다.**

### 6-3. 아직 아무도 안 한 것

- **예나 제안**: TrackMan을 정적 통계가 아니라 **유사투수 prior**로 재시도 (클러스터링)

- **승주 지적**: `xgb_insight_adjusted_t93`이 단일 시드인데 가중치 0.6085 — 여기만 20시드로 올리면 +1.16 BSS

## 7. 팀 검증 프로토콜 (통일안)

지금까지 다섯 명이 각자 다른 기준을 썼습니다. 앞으로는 이렇게 통일합시다.

**1. 노이즈를 먼저 잰다.**
같은 설정으로 시드만 바꿔 **5~8회**. 그 산포가 측정 한계입니다.
(예나: 3시드로 판단했다가 8시드에서 뒤집힌 사례 2건)

**2. 최소 2개 연도, 가능하면 3개.**
2022(정상) + 2023(레짐 변화) + 2024(직전). **2024만 보면 안 됩니다.**

**3. 한 번에 하나씩만 바꾼다.**
정희원 v6는 6개를 묶어 냈다가 실패해서 **원인 분리가 불가능**해졌습니다.

**4. 변경 종류에 따라 기준을 다르게 둔다.**

| 종류 | 채택 기준 |
|---|---|
| 새 피처 | 노이즈의 **1.5배 이상** + 2개 연도 이상 일관 |
| 앙상블/배깅/캘리브레이션 | 노이즈 이상이면 채택 (전이율이 높음) |

**5. 검증 이득은 절반으로 할인해서 기대한다.**
찬우 플래툰: val +85 → LB +32.5. 승주 residual: 90.5% 전이.
**피처는 40%, 구조 변경은 90%** 정도로 잡으면 실제와 비슷합니다.

1. 각자 최고점 제출물의 예측 CSV를 공유 → 상관 행렬 계산 (**반나절**)
2. `w* = M⁻¹A`로 결합 가중치 산출 및 예상 점수 확인 (**한 시간**)
3. 예상이 1000점을 넘으면 → 통합 `script.py` 제작 → **한 번 제출**

**그다음**
4. 트리 깊이 단독 검증 (찬우 라인 미검증 항목)
5. 서로의 기법 한 개씩 교차 적용 (isotonic / residual / 축소계수)

**하지 말 것**
- TrackMan 물리 피처
- 선수 ID 임베딩
- 매치업 히스토리
- 새 상호작용 피처 탐색 (플래툰 외에 살아남은 게 없습니다)

---

> **한 문장으로**: 우리는 각자 100점씩 흩어져 있는데, 흩어져 있다는 사실 자체가
> 가장 큰 자산입니다. 서로 다르게 틀리기 때문에 합치면 오차가 상쇄됩니다.
> 더 파는 것보다 합치는 것이 먼저입니다.

## 부록. 용어 사전

| 용어 | 쉬운 설명 |
|---|---|
| **AUC** | 성공/실패 하나씩 뽑았을 때 성공 쪽에 더 높은 점수를 주는 비율. 0.5 = 동전 던지기 |
| **Brier Score** | (예측확률 − 정답)²의 평균. 작을수록 좋음 |
| **BSS** | Brier를 "상수 예측"과 비교한 값. 대회 점수 = BSS × 100,000 |
| **베이스율** | 전체에서 정답이 1인 비율. 여기서는 시즌 제구 성공률 |
| **캘리브레이션** | 예측 확률의 눈금을 실제 빈도에 맞추는 것. 저울 영점 맞추기 |
| **로짓** | `log(p/(1−p))`. 확률을 실수 전체로 펼치는 변환. 범위를 안 벗어나고 이동시킬 때 씀 |
| **배깅** | 데이터를 조금씩 다르게 뽑아 여러 모델을 학습 후 평균. 무작위 오차 상쇄 |
| **residual 적층** | 기본 예측 위에 작은 보정항을 얹는 구조 (승주 방식) |
| **EB 축소** | 표본이 적은 대상의 추정치를 전체 평균 쪽으로 끌어당김. "가상 관측 K개 추가" |
| **플래툰 스플릿** | 투수의 좌타 상대 성적과 우타 상대 성적의 차이 |
| **누수(leakage)** | 예측 시점에 알 수 없는 정보가 피처에 섞이는 것. 검증만 좋아지고 실전에서 무너짐 |
| **승자의 저주** | 여러 후보 중 최고를 고르면 그 측정치가 실제보다 위로 편향되는 현상 |
| **OOV** | out-of-vocabulary. 학습에 없던 신규 선수 |
| **전이율** | 검증 개선이 실제 리더보드에 반영된 비율 |
