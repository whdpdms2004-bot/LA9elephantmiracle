## 4. 결정 3 — 보정 분산 조정 기각 (smoothing / sharpening)

Brier에서 최적 mean-preserving spread 배수는 닫힌 형태다: `a* = Cov(p,y)/Var(p)`. `a*>1`이면 sharpening, `<1`이면 smoothing이 필요하다.

| 대상 | a* | 투수 블록 95% CI | 정직 검증 ΔBSS | 개선 월 |
|---|---:|---|---:|:---:|
| 전체 | 1.047 | [0.975, 1.108] | **−2.52** | 4/8 |
| R | 1.030 | [0.948, 1.091] | **−3.52** | 3/8 |
| F | 1.285 | [0.991, 1.542] | +16.92 | 6/8 |

정직 검증 = leave-one-month-out (월 하나를 빼고 7개월로 `a`를 적합해 뺀 월에 적용).

**전체·R은 in-sample로 +1.66 BSS 이득처럼 보이지만 정직하게 적합하면 2.5~3.5를 잃는다.** 10분위 reliability에서 9개 구간의 gap이 ±0.007 이내이고, `a*>1` 신호는 최상위 분위(pred 0.566 → obs 0.581) 한 칸에서 거의 전부 나온다.

그리고 이미 적용된 상태였다 — 시스템별 a*: **013 = 1.073 → 019 = 1.044 → 022 = 1.047.** R context와 F expert residual을 더한 작업 자체가 보정 기울기를 1로 밀어내는 작업이었다.

**F만 예외**(a* = 1.285, 정직 검증 F BSS +16.92 = 전체 +1.99)지만, CI가 1.0을 아슬아슬하게 포함하고 현행 F 가중치는 2023 월별 OOF에서 선택해 2024로 이전한 값이라 2024 재조정은 프로토콜 위반이다. **보류.**

## 5. 결정 4 — confidence 조건부 shrinkage 기각

"신뢰도 낮은 행은 더 축소한다"를 다음 형태로 검증했다.

```
p'(x) = m + a(x)·(p(x) − m),    a(x) = w₀ + Σ wₖ·zₖ(x)
```

Brier 최소화가 OLS이므로 닫힌 해로 적합된다. `zₖ`는 타깃과 무관한 신뢰도 피처만 사용했다: 표본량(`asof_pitcher_n`, `asof_batter_n`), 모델 불일치 `|ensemble−adjusted|`, seed 불일치 `|reverse20−reverse3|`, 결측 플래그, F 여부.

| 구성 | in-sample | 정직 검증 (LOMO) | 개선 월 |
|---|---:|---:|:---:|
| 전역 a | +1.66 | −2.52 | 4/8 |
| a(x) 전체 | +7.29 | **−5.90** | 3/8 |
| a(x) 표본량만 | — | −6.02 | 4/8 |
| a(x) 모델 불일치만 | — | −0.78 | 4/8 |
| a(x) seed 불일치만 | — | −1.69 | 4/8 |

전부 음수이고, confidence를 넣으면 전역 a보다 더 나빠진다. 파라미터 6개에 13점 과적합 갭.

**이유: 이미 구현돼 있다.** 예측 표준편차가 confidence에 따라 이미 단조 증가한다.

| `asof_pitcher_n` | n | 예측 sd |
|---|---:|---:|
| 0 | 81 | 0.01758 |
| 1~100 | 7,908 | 0.03607 |
| 101~1,000 | 50,745 | 0.03779 |
| 1,001~4,000 | 100,849 | 0.04226 |
| > 4,000 | 93,924 | 0.04326 |

cold start 투수는 베테랑 대비 예측 폭이 40% 수준이다. `prior_strength=200` Bayesian smoothing, 클러스터/pair smoothing 1000/5000, unknown pair의 0-residual fallback이 confidence 조건부 축소를 **피처 단계에서** 이미 수행한다. 사후 계층은 이중 축소다. 표본량 방향도 직관과 반대로, 저표본 행이 오히려 sharpening을 원한다(하위 3분위 a* 1.082 vs 상위 3분위 1.021).

## 8. 결정 7 — 2025 시즌 고정 logit offset 채택

여기가 이번 제출의 유일한 신규 요소다.

### 문제

학습 데이터에 2025가 없다. 실측으로 확인한 결과, **모델은 `season=2025`에 완전히 무반응이다** — 동일 245,789행에 대해 `season`을 2024와 2025로 바꿔 추론한 결과가 비트 단위로 동일했다(max |Δ| = 0.0000000000). 트리가 학습 범위 밖을 외삽하지 못하는 구조다. `insight_prior_constants`의 `prior_last`도 2024 성공률 0.4861에 고정돼 있다.

즉 시스템 전체의 레벨 앵커가 2024에 박혀 있는데, 실제 타깃은 2025다.

### 레버리지

Brier에서 보정된 예측에 평균 편차 δ가 있으면 δ²가 그대로 더해진다. `ΔBSS = 100000·δ²/null`.

| \|δ\| | BSS 손실 |
|---:|---:|
| 0.50%p | 10.0 |
| 1.00%p | 40.0 |
| 2.00%p | 160.1 |

**평균이 0.8%p만 어긋나도 013→021 체인 전체 이득(+23.8)이 사라진다.** 이 문제에서 가장 레버리지가 큰 단일 축이다.

### 근거

연도별 `control_success` 평균:

| 시즌 | 2019 | 2020 | 2021 | 2022 | 2023 | 2024 |
|---|---:|---:|---:|---:|---:|---:|
| 성공률 | 0.5647 | 0.5327 | 0.5328 | 0.5289 | 0.5000 | 0.4861 |

2019→2024에 −7.86%p. 동일 투수 통제(양 시즌 100구 이상, 투구수 가중) YoY도 −3.17 / +0.19 / −0.78 / −2.37 / −1.02 %p로, 선수 교체만으로 설명되지 않는 실제 하락이다.

**2025 목표 성공률을 0.4792로 고정한다** — 2024의 0.4861에서 최근 연간 하락폭의 50%를 추가 반영한 값이다.

```
2023 → 2024 실측 변화 = −1.386%p
그 50%                = −0.693%p
0.48610 − 0.00693     =  0.47917  →  0.4792
```

reference rate 0.4861 → 목표 0.4792의 고정 logit offset:

```
logit(0.4861) = −0.0556143299
logit(0.4792) = −0.0832480441
offset        = −0.0276337141
```

세 값 모두 배정밀도로 재계산해 일치를 확인했다.

### 원칙

**2025 평가 데이터의 분포·예측 평균을 이용한 재계산이나 재보정은 수행하지 않는다.** 2019~2024에서 사전 결정한 상수를 추론 시 그대로 적용한다. test 행 간 집계 금지 규정에도 부합한다.

### 구현

`script.py` 최종 예측 직후, 유효성 검사 직전에 삽입한다.

```python
offset = float(metadata.get("season_logit_offset", 0.0))
if offset != 0.0:
    bounded = np.clip(prediction, 1e-7, 1.0 - 1e-7)
    prediction = 1.0 / (
        1.0 + np.exp(-(np.log(bounded / (1.0 - bounded)) + offset))
    )
```

값은 `metadata.json`의 `season_logit_offset`에서 읽으므로 코드 수정 없이 조정 가능하다.

## 13. 알려진 위험

`script.py`의 `raw[~np.isfinite(raw)] = np.nan`(TabM 전처리)은 **pandas 3.x에서 실패한다.** Copy-on-Write가 강제되면서 `Series.to_numpy()`가 읽기전용 배열을 반환하기 때문이다.

- 고정 환경 pandas 2.2.2에서는 정상이며 위 스모크가 이를 증명한다.
- 이번 제출이 916.70으로 정상 채점됐으므로 **평가 서버의 pandas는 3.x가 아님이 확인됐다.** 이 위험은 이번 제출로 해소됐다.
- 다만 `requirements.txt`에 pandas가 고정돼 있지 않으므로 서버 이미지가 갱신되면 재발할 수 있다. 하드닝은 한 줄이다: `raw = np.array(raw, dtype="float64", copy=True)`.
