**"투수별 모델링"은 이 표의 1행에 걸린다.** 그래서 Phase D는 완전분리가 아니라 **부분 풀링(전체 모델 + 투수 residual)** 으로만 설계했다. 완전분리는 비교군으로 한 번 재현하고 끝낸다.

**"아웃카운트·중요도"는 2·3행에 인접한다.** 47개 원본 컬럼은 이미 **전부** 모델에 들어가 있다(`UNUSED_FEATURE_AUDIT.md`). 따라서 "아웃카운트가 성공률과 관계있다"는 마진 통계는 무가치하고, **"모델이 아웃카운트 구간에서 체계적으로 틀리는가"** 만 가치가 있다. Phase B는 그것만 잰다.

반대 근거도 있다: 같은 축에서 **R context residual(count × inning × hand)은 성공했다**(013→015, +17.8 BSS). 원본 피처가 있어도 residual 형태로 다시 넣으면 먹히는 축이 존재한다. 그래서 Phase B를 아예 건너뛰지는 않는다.

### Phase B — 슬라이스 잔차 진단 (08.15~08.16)

사용자 요청 ①("아웃카운트별·경기중요도별 성능 확인")의 정확한 구현.

**측정 대상**: 현행 예측의 잔차 `y - p̂`. 성공률이 아니다.

| 축 | 셀 수 |
|---|---:|
| `outs_before` | 3 |
| `li` 10분위 + `high_leverage` | 11 |
| `outs_before` × `base_state` (= `runner_out_state`) | 24 |
| `outs_before` × `count_state` | 36 |
| `li` bucket × `count_state` | 60 |
| `inning` bucket × `outs_before` | 12 |
| `score_diff` bucket × `li` bucket | 25 |
| `game_month` × `outs_before` | 24 |

**지표**: 셀별 평균 잔차 + t통계 + **잔차검정비** (셀 평균 잔차의 실제 분산 / 이항 기대 분산). 찬우가 쓴 것과 같은 축이라 팀 내 수치가 바로 비교된다 — 1.03 = 무신호, 0.60~0.64 = 무신호.

**2023과 2024 두 연도에서 각각 측정한다.** 2024 단독 신호는 채택 근거가 아니다.

> **게이트 B**: 잔차검정비 ≥ 1.5인 축이 **두 연도 모두**에서 나오지 않으면 상황 축은 **여기서 종료**하고 예산 전부를 Phase D로 옮긴다.
>
> 솔직한 사전 기대: **낮다.** 찬우가 인접한 두 축에서 이미 무신호를 봤고, 원본 47컬럼이 전부 모델에 있으며, R context residual이 count×inning×hand를 이미 흡수했다. 하루 반 이상 쓰지 않는다.

### Phase C — 상황 residual 확장 (08.16~08.18, **게이트 B 통과 시에만**)

현행 R context residual = `count_state × inning_bucket × pitcher_hand × batter_hand`, smoothing 5000, scale 1.15.  
여기에 **축을 하나씩만** 추가한다. 한 번에 하나 (plan.md 검증 프로토콜 §3).

| 후보 | 추가 축 |
|---|---|
| C1 | `+ outs_before` |
| C2 | `+ li bucket` (3~5구간) |
| C3 | `+ 득점권 여부` (2값 압축) |

- smoothing / scale은 **2022·2023에서만** 정한다. 2024는 마지막 1회 게이트.
- 채택: 2022·2023 **둘 다** σ×1.5 이상 개선 **and** 2024 부호 일치.
- 셀이 잘게 쪼개지므로 smoothing을 5000보다 키우는 방향부터 본다.

### Phase D — 투수 부분 풀링 (08.18~08.23) — **본 라인의 주력**

사용자 요청 ②("투수별 모델링")의 정확한 구현. 완전분리는 하지 않는다(§1).

**대상 임계: 2019~2023 누적 200구 이상 = 516명, 2024 행의 77.45%.** 근거는 [`10_PITCHER_COVERAGE.md`](10_PITCHER_COVERAGE.md) §7.  
2025 추론 시에는 2019~2024 누적 200구 이상으로 한 해 민다.

| # | 실험 | 설계 |
|---|---|---|
| D1 | **투수 절편 residual** | 전체 모델 로짓에 투수별 offset. shrinkage prior + recency weight. 미달 투수는 0 → base 보존 |
| D2 | **투수 × 상황 residual** | Phase B/C에서 살아남은 축과의 교호작용만. 살아남은 축이 없으면 D2 생략 |
| D3 | **임계 민감도** | 누적 100 / 200 / 500 세 값 전부를 2022·2023·2024에서 측정 |
| D4 | 완전분리 (비교군) | 채택 기대 없음. 0723 결론 재현 확인용 1회 |

**D3를 반드시 하는 이유**: 임계값 하나를 2024 성능만 보고 고르면 selection overfit이다. 세 값의 커버리지-정밀도 곡선을 그린 뒤 고른다.

> **게이트 D**: D1이 σ×1.5를 못 넘으면 D2·D4를 중단하고 Phase E로 간다.
>
> **가장 유력한 실패 시나리오**: `asof_pitcher_success_rate` + prior 200 Bayesian smoothing + reliability가 이미 투수 절편을 흡수했을 가능성. 이 경우 D1의 순증분이 0에 가깝다. D1을 먼저 돌리는 이유가 이것이다 — **싸고, 실패하면 D 전체를 죽인다.**

**커버리지가 이득의 상한이라는 점을 계산에 반영한다.** 커버 구간에서 Brier를 x만큼 줄여도 전체 이득은 0.7745x다. cold start 19.86%는 정의상 0이다.

### Phase E — 팀 결합 (08.20 착수, 08.26 병합) — **최대 기회, 늦추지 않는다**

plan.md 1순위. **sj 혼자 못 하므로 08.20까지 팀에 요청을 넣어야 한다.** Phase C/D 결과를 기다리지 않는다.

1. 5명이 **공통 Val2024 split**에서 예측 CSV 공유 (같은 `row_id` 순서)
2. 상관 행렬 → 결합 이득 확인 (0.85 이하면 크다)
3. `w* = M⁻¹A`, 단 **A·M 모두 홀드아웃 2024 실제 라벨에서** 산출
4. 견고성: `V` ±15%, 가중치 ±0.1 흔들어 평평한지
5. 통합 `script.py` → **한 번만 제출**

> ⚠️ **규정 리스크 — 팀에 먼저 합의를 받을 것.** 팀통합 문서 §5-3은 `A`를 **리더보드 점수에서 역산**한다. 이는 평가 데이터 라벨에 fitting하는 것이라 `RULES.md` §2·§9·§10-A 위반 소지가 크다. 수식은 그대로 두고 **출처만 홀드아웃 2024로** 바꾸면 09.11 코드 검증에서 방어 가능하다. 상세는 plan.md의 해당 절.

추론 시간도 확인한다. 5인분을 합치면 245,789행 / 10분 제한에 걸릴 수 있다(현재 sj 단독 162초).

## 4. 채택 기준 (전 단계 공통)

plan.md 검증 프로토콜을 그대로 따른다.

1. **노이즈를 먼저 잰다.** 같은 설정 시드 5~8회. 그 산포가 측정 한계다.
2. **최소 2개 연도.** 2022(정상) + 2023(레짐 변화) + 2024(직전). **2024만 보면 안 된다.**

4. **채택 기준** — 새 피처는 σ×1.5 이상 + 2개 연도 일관. 앙상블/배깅/캘리브레이션은 σ 이상이면 채택.
5. **검증 이득은 할인해 기대한다** — 피처 40%, 구조 변경 90% 전이. (실측: 013→022 체인의 Public 전이율 90.5%)
