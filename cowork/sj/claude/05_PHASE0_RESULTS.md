## P0-1. 선택 과적합 진단 (결론 1·2)

예측 벡터 대신 **탐색 그리드의 F23 / F24 순위 상관**으로 판정했다. 두 fold의 순위가 무관하면 F24 최댓값 선택은 노이즈 추적이다.

| 그리드 | n | spearman(F23,F24) | 양 fold 개선 | F24-best의 F23 백분위 | top10% Jaccard |
|---|---:|---:|---:|---:|---:|
| **구조 선택** | | | | | |
| `joint_svd_cluster_grid` | 5,670 | **+0.061** | 25.9% | 32.5% | **0.03** |
| `deep_pitcher_cluster_grid` | 8,232 | **+0.078** | 31.2% | 5.2% | 0.12 |
| ┗ pitcher_config 단위 최선값 | 56 | **+0.123** | — | — | — |
| **강도 선택** | | | | | |
| `dual_matchup_scale_tuning` | 625 | +0.838 | 53.4% | 25.1% | 0.02 |
| `reverse_batter_seed_joint_tuning` | 4,284 | +0.820 | 94.9% | 16.7% | 0.26 |
| `dual_reverse_batter_scale_tuning` | 625 | +0.688 | 72.3% | 25.8% | 0.00 |
| `large_xgb_correction_grid` | 1,089 | +0.625 | 99.0% | 6.7% | 0.27 |
| **최종 후보 선발** | | | | | |
| `joint_svd_outer_search` | 108 | +0.537 | 100% | 10.2% | 0.18 |
| `joint_svd_stable_search` | 432 | +0.472 | 100% | **70.8%** | **0.01** |

### 읽는 법

**구조 선택은 전이되지 않는다.** 군집 알고리즘·PCA 차원·K·SVD dim·λ를 바꿀 때 F23과 F24의 순위 상관이 **0.06~0.12**다. 양 fold 동시 개선도 26~31%뿐이다. top10% Jaccard 0.03은 F23 상위 10%와 F24 상위 10%가 거의 완전히 다른 집합이라는 뜻이다.

→ **"어떤 군집 구조가 좋은가"에 대한 2024 기준 답은 2023에 대해 정보가 없다.** 56개 구조 × 5 seed × PCA × 알고리즘의 탐색(문서 기재 56~180 구조)에서 나온 최적 구조는 그 fold의 우연이다.

**강도 선택은 전이된다.** correction scale·Ridge alpha 같은 연속 강도 파라미터는 spearman 0.62~0.84로 안정적이다. 이 축의 튜닝은 신뢰할 수 있다.

**결정적 관찰**: 최종 후보를 뽑은 `joint_svd_stable_search`(432행)에서 **F24 1위 후보의 F23 순위는 상위 70.8%** — 즉 432개 중 하위 30% 수준이다. 이 후보가 문서상 `815.0828`(공동 SVD 공격형)이다. 원본 JSON에도 근거가 남아 있다.

| 후보 | F23 ΔBrier | F24 ΔBrier | 2024 BSS |
|---|---:|---:|---:|
| `best_outer` (공격형, 문서상 내부 최고) | **−7.575e-06** | −2.443e-05 | 815.0828 |
| `best_robust` | **−3.817e-05** | −3.120e-05 | 813.7412 |

공격형의 F23 개선폭은 robust의 **1/5**다.

반면 `submit_013`을 만든 `reverse_batter_seed_joint_tuning`은 spearman 0.820, 양 fold 개선 94.9%, F24-best의 F23 백분위 16.7%로 **훨씬 건전한 선택**이었다. Public LB 895.404가 확인된 것과 일관된다.

### 조치

1. **공동 SVD 공격형(815.083)의 제출 우선순위를 올리지 않는다.** 팀의 기존 판단이 옳았다.
2. **구조 선택은 F24 점수로 하지 않는다.** `min(F22, F23, F24)` 또는 `robust_objective`만 사용하고, `best_outer`를 문서에 병기하지 않는다 (병기 자체가 유혹이다).
3. 향후 모든 구조 탐색은 **F22·F23에서 선택하고 F24는 단 한 번만 확인**하는 nested 방식으로 한다.

## P0-2. TrackMan 피처 전처리 감사 (결함 확정)

`trackman500_cutoff.py:310-316` 확인:

```python
season_metric = rows.groupby(["pitcher_trackman_id","season"])[TM_METRICS].agg(["mean","std"])
```

**8개 물리량이 원시 절대값으로 집계된다.** `season × pitch_type_group` robust z가 없다. 문서(`INSIGHTS_SUMMARY.md`)의 "원시 절대값보다 시즌·구종 내 z-score를 사용" 방침이 코드에 반영되지 않았다.

## P0-3. 임베딩 감사 (결론: 계열이 아니라 구현이 실패했다)

`pitcher_season_embedding_oof.csv`(2,260행 × 58열)를 직접 측정했다.

### 3a. YoY 안정성이 사실상 0

| 그룹 | 21→22 코사인 | 22→23 | 23→24 | 차원별 YoY R² |
|---|---:|---:|---:|---:|
| `pitcher_embedding` (16d, 타깃 지도) | −0.005 | +0.054 | +0.076 | **0.0035 ~ 0.0049** |
| `trackman_embedding` (24d) | +0.024 | +0.004 | +0.049 | 0.070 ~ 0.115 |
| `cohort_embedding` (8d) | **−0.203** | +0.166 | **−0.267** | 0.063 ~ 0.119 |

참고선: Stuff+ **0.702** / Kirby Index **0.50** / 팀 자체 Kirby 재현 0.26~0.34.

`cohort_embedding`의 코사인이 시즌마다 **부호가 뒤집힌다.** 원인은 코드에서 확인된다 — `train_strict_multitask_embedding.py`가 fold마다 `torch.manual_seed(SEED + fold + args.embedding_dim)`으로 재학습하고 **latent 정렬 단계가 없다.** 신경망 latent는 재학습마다 임의 직교변환만큼 회전하므로, GBDT가 2021 임베딩에서 배운 분할 임계값이 2022 임베딩에서는 무의미하다. **2025 외삽은 원리적으로 불가능한 상태였다.**

### 3b. TrackMan 타워 오염 (완전 분리)

| 항목 | 실측 |
|---|---|
| 2021~2024 `tm_available=1` / `=0` | 863 / 686 |
| 미가용 집단의 24차원 unique 벡터 수 | **4개** (686건이 4가지 폴백 값) |
| 벡터 norm 평균 (가용 / 미가용) | 1.2695 / **1.9082** (폴백이 더 극단) |
| **임베딩 24차원만으로 `tm_available` 예측 AUC** | **0.9983** |

24차원의 지배적 신호가 "TrackMan 보유 여부"다. 그건 이미 `tm_available` 플래그로 존재한다. 게다가 가용 투수 성공률 49.29% vs 미가용 47.58%(1.7%p 차)이므로, 24차원이 그 차이를 중복 인코딩하며 트리 분할을 낭비한다.

### 3c. 타깃 지도 학습

`train_strict_multitask_embedding.py`: `TARGET = "control_success"`, `loss = brier + aux_weight * auxiliary`. `pitcher_embedding` 16차원은 `control_success`를 타깃으로 학습된 ID 임베딩 = **학습된 target encoding**이다. 팀은 이미 전체 temporal TE로 BSS 361.06을 기록했는데, 같은 함정을 임베딩 형태로 다시 밟았다.

부수적으로 `cohort_embedding = nn.Embedding(5, dim)`은 5개 값의 lookup이므로 `experience_cohort` 컬럼 하나와 정보량이 같다. 8차원 낭비.

### 3d. 반증도 하나 있다

`strict_tm500_multitask_dim32`는 **F23 fold 659개 실험 중 AUC 최고(0.531877)** 였다. XGBoost V1(0.529329), enhanced_robust(0.529003), LightGBM(0.528944)을 모두 앞섰다. 드리프트가 가장 심한 fold에서 순위 신호를 가장 잘 보존한 것이다. 무너진 것은 캘리브레이션(mean_gap +0.028)이었다.

→ **임베딩을 확률 예측기로 쓰지 말고 순위·보정 신호로 쓰라**는 근거. 단, P0-4의 상한 결과(아래)를 함께 보면 기대값은 낮춰야 한다.

### 해석 — 네 가지

**① 투수-시즌 수준 표현은 이미 소진됐다.**
O1의 상한은 AUC 0.5446 / BSS 720.9다. 팀의 현재 단일 모델은 이미 **AUC 0.5498 / BSS 784.6**으로 그 상한을 넘었다(상황 변수와의 상호작용 덕이다). TrackMan 요약통계와 투수 임베딩이 담을 수 있는 정보는 본질적으로 **투수-시즌 상수**이므로, 이 축의 추가 개선 여지는 매우 얇다.

→ **원래 계획의 핵심 전제("TrackMan 임베딩으로 AUC 천장을 공격")를 부분 철회한다.** 정직하게 말하면, 더 좋은 투수 표현으로 얻을 수 있는 것은 크지 않다.

**② 그러나 `투수 × 타자손` 조건부에는 헤드룸이 있다.**
O2 상한이 **BSS 917.7**이고 현재 내부 최고는 815.08이다. **약 +100의 여지**가 남아 있다. O3b를 BASE에 넣으면 **864.6 (+297.6)**, O4는 812.0 (+245).

→ **가치는 "투수가 누구인가"가 아니라 "투수가 이 상황에서 어떻게 반응하는가"에 있다.** 이것이 `01_TRACKMAN_FEATURE_CATALOG.md`의 Tier E이고, 팀의 상성 correction이 이미 부분적으로 하고 있는 것이다. Tier E를 유일한 최우선 축으로 승격한다.

**③ 타자 개별 표현은 유해하다.**
O6 상한이 BSS 43.0(거의 무정보)이고, BASE에 넣으면 **−2008.6**으로 대폭 악화한다. 팀이 "타자 GMM은 양 fold 동시 개선 없음"으로 폐기한 것과 정확히 일치한다.

→ **타자는 손(hand)과 군집 수준까지만 쓴다.** 개별 타자 임베딩·타자 ID 피처는 만들지 않는다.

**④ 개별 매치업과 이닝 조건부는 가치가 없다.**
O4는 셀당 median n=13으로 너무 희소해 oracle조차 AUC 0.5407이다. O7(이닝)은 BASE에 넣으면 330.7로 악화한다.

→ **최적 해상도는 `투수유형 × 타자손(또는 타자유형) × 볼카운트`다.** 개별 매치업을 파고들 필요 없고, Tier B의 `inning` 상호작용 기대치는 낮춰야 한다.

### ⑤ 그리고 가장 실무적인 발견 — 절대 확률로 넣으면 파괴된다

O1과 O6는 **완벽한 정보(oracle)인데도** BASE에 추가하면 BSS가 −1163 / −2009로 무너진다. pred_mean도 0.4819 / 0.4916으로 어긋난다.

원인: 학습 시즌 성공률(0.4861~0.5647)과 검증 시즌 수준이 다르므로, 트리가 학습 분포에서 배운 임계값이 검증에서 계통 편향을 만든다. 셀이 잘게 쪼개진 O3b·O4는 절대 수준이 희석되어 개선된다.

→ **이것이 팀이 "군집·matchup 피처 직접 투입 748~761"로 실패한 메커니즘의 정체다.** 대응은 하드 규칙으로 승격: **TrackMan 유래 신호는 절대 수준이 아니라 `시즌 × 손 × 카운트` 평균을 제거한 잔차로만 투입한다.**

| 25% | 305,396 | 0.5423 | 536.5 |
| 50% | 610,792 | 0.5434 | 557.3 |
| **100%** | **1,221,585** | **0.5435** | **567.0** |
| 2022~2023만 | 492,997 | 0.5420 | 518.5 |

**50% → 100%에서 AUC +0.0001, BSS +9.7 (전체의 1.7%).** 완전히 포화했다.

> **결론: 타깃 모델에 대한 데이터 증강은 효과가 없다.** 표본 수는 병목이 아니다. mixup·SMOTE·pseudo-labeling에 시간을 쓸 이유가 없다. (덧붙여 pseudo-labeling은 "평가 데이터 전체를 보고 만든 사후 보정값" 금지 조항에 걸릴 소지가 크다.)

부수적으로, 최근 2시즌(40%)만 써도 518.5로 손실이 작다 → 오래된 시즌의 한계 가치가 낮다. 시즌 가중을 최근 쪽으로 더 기울이는 실험은 저비용으로 해볼 만하다.

## P0-6. R/F 분리 모델 검증 (결론 6)

`game_type`으로 dispatch하는 구조를 F22·F23·F24 세 fold에서 실측했다. 평가는 공식 방식대로 pooled 예측 벡터의 BSS이고, 목적함수 `J = 0.10·NB22 + 0.25·NB23 + 0.65·NB24`에 대응하는 가중 BSS를 함께 계산했다.

### 결과 (BASE 43피처, 고정 250 라운드)

| 구성 | F22 | F23 | F24 | 가중 J BSS | R 서브셋 F24 |
|---|---:|---:|---:|---:|---:|
| **A 단일 모델 (현행)** | 2218.1 | −1101.9 | 567.0 | **314.9** | 595.8 |
| B 완전 분리 (R모델 + F모델) | 2234.6 | **−1436.6** | 594.1 | 250.6 | 623.2 |
| C 분리 + F는 단절 이후만 | 2176.0 | −1994.3 | 583.7 | 100.0 | 623.2 |
| D 단일 + 단절 이전 F 행 제외 | 2201.6 | −1402.8 | 597.4 | 256.2 | 613.3 |
| **G 부분 분리 (R행→R모델 / F행→단일)** | 2232.3 | −1106.1 | **591.2** | **331.0** | **623.2** |
| H G + F 평균 shift ×0.25 | 2223.8 | −1135.2 | 570.0 | 309.0 | 623.2 |
| H G + F 평균 shift ×0.5 | 2162.5 | −1164.4 | 308.8 | 125.9 | 623.2 |
| I 단일, F sample weight 0.5 | 2216.2 | −1119.5 | 566.0 | 309.7 | 602.7 |
| I 단일, F sample weight 2.0 | 2175.2 | −1161.4 | 564.3 | 294.0 | 596.4 |
| J R전용 모델을 R·F 양쪽에 | 813.4 | **533.2** | 572.1 | (586.5) | 623.2 |

### 해석

**완전 분리(B)는 순손실이다.** F22 +16.5, F24 +27.2를 얻지만 F23에서 **−334.7**을 잃어 가중 −64.3이다. 원인 두 가지:
- **F 모델의 표본 고갈** — F는 시즌당 25,686~30,448행뿐이다. 체제 단절 이후만 쓰면 2023+2024 = 55,696행이고, P0-5의 학습곡선상 152,698행에서 이미 BSS 347로 열화한다. C(단절 이후만)가 오히려 더 나쁜 것(−1994.3)이 이를 확증한다.
- **체제 단절 취약성** — F 성공률은 2022 70.87% → 2023 47.29%로 무너졌다. 단절 이전 F로 학습한 F 전용 모델은 단절 이후 F에서 F BSS −19,174 (단일 모델은 −16,006)로 더 크게 틀린다.

**부분 분리(G)는 순이득 +16.1이다.** R 행은 R 전용 모델, F 행은 단일 모델이 담당한다.
- F22 +14.2, F24 **+24.2**, F23 −4.2 (손실이 매우 작다)
- AUC도 F24에서 0.5435 → **0.5444** 상승
- R 서브셋에서 F22 462.7 → 478.9 (+16.2), F24 595.8 → **623.2 (+27.4)**. R은 2024 행의 88.16%이므로 이 이득이 지배적이다.

**이득의 원천은 "F 모델을 따로 만든 것"이 아니라 "R 모델 학습에서 F 행을 뺀 것"이다.** F 행이 R 모델을 오염시키고 있었다. F는 성공률·실패 구성이 R과 구조적으로 다르므로(F reverse 2022 4.82% → 2023 29.96%) 같은 트리에 넣으면 R의 분할이 왜곡된다.

**dispatch 자체는 안전하다.** `game_type`은 train/test 양쪽에 존재하는 정식 컬럼이고, TrackMan 가용성(투수 경력과 상관 — 가용 `asof_pitcher_n` 중앙값 4,440 vs 미가용 837)과 달리 **선택 편향이 없다.** 그래서 팀의 gated 실패(678.85)가 재현될 위험은 낮고, 실제로 G가 이득을 냈다.

**J는 함정이다 — 그리고 목적함수의 결함을 드러낸다.**
J(R 전용 모델을 F 행에도 적용)의 가중 BSS 586.5는 표면상 압도적 1위다. 그러나:
- F22에서 −1404.7 대폭 악화 (F BSS −14,018). 2022 F 실제 성공률 70.87%를 R 수준 50.37%로 예측하니 당연하다.
- F23에서 +1635.1 대폭 개선 (F BSS −289.6 vs −16,006). **2023 F가 마침 R과 비슷해졌기(47.29% vs R 50.31%) 때문의 우연이다.**
- 가중 목적함수가 J를 1위로 뽑은 것은 `F23 가중 0.25 × 우연한 +1635 ≈ +409`가 지배한 결과다.

이는 `00_ASSESSMENT.md` §4에서 지적한 "**F23은 모델 품질이 아니라 평균 편향을 재는 fold**"라는 진단의 실증이다. **목적함수 J를 그대로 믿으면 J 같은 구조적으로 위험한 구성이 1위로 뽑힌다.**

### 조치

1. **G(부분 분리)를 채택 후보로 승격한다.** 다만 여기서 쓴 BASE 43피처 대신 실제 파이프라인(211피처 + insight prior + TrackMan)에서 재검증해야 한다. 이득이 유지되면 R 전용 모델을 앙상블 멤버로 추가한다.
2. **B·C(완전 분리)는 폐기한다.** 사용자 제안의 원형이지만 F 표본 고갈과 체제 취약성으로 순손실이다.
3. **H(F 평균 shift)·I(sample weight)도 폐기한다.** F 평균을 직전 시즌 기준으로 이월하는 것은 0.25배로 축소해도 악화한다 — 팀이 "강하게 축소된 보정"을 쓰는 이유가 확인됐다.
4. **목적함수에 F23 가중 0.25를 그대로 두면 위험하다.** `R-only F23 ΔBrier`를 하드 게이트로 승격하고, F23 전체 점수는 참고 지표로 내린다. J 단독으로 후보를 정렬하지 않는다.
5. 제출 ZIP 영향은 무시할 수 있다 — XGB 모델 1개 추가는 약 6MB이고 현재 104~106MB / 16~18초에 여유가 있다.
