## 0. 먼저 확정 — test 시점에 무엇이 있는가

계획 전체가 이 표 위에 선다. 착각하면 전부 무효다.

| 정보 | test.csv에 있나 | 비고 |
|---|---|---|
| 누적 성공률 `asof_pitcher_success_rate` | **있음** | 커리어 |
| 누적 **실패 구성** `reverse` / `middle` / `ball` / `strike` rate | **있음** | ★ 4개 전부 제공된다 |
| 구종 구성 `fastball` / `breaking` / `offspeed` rate | **있음** | |
| 최근 폼 `prev1/3/5_game_success_rate` | **있음** | 1.98% 결측 |
| 최근 폼 `prev1/3/5_game_middle_rate` | **있음** | 최근은 middle만, reverse·ball 없음 |
| 표본량 `asof_pitcher_n` | **있음** | |
| 투구별 성분 라벨 (MIDDLE/REVERSE/OUTSIDE) | **없음** | train에서 유도, **학습 전용** |

**핵심.** 투수의 **커리어 실패 구성 프로파일**은 복원 없이 공식 컬럼에서 그대로 나온다. 유형화의 재료가 이미 입력에 들어 있다는 뜻이고, 규정 논쟁이 전혀 없는 영역이다.

그리고 이 값들은 **행마다 다르다** (as-of라 시즌 중 갱신). 따라서 —

> **유형 배정은 행 단위로 한다.** 클러스터 중심은 학습 데이터로 fit하고, 각 행은 자기 `asof` 벡터로 배정받는다. test 행끼리 참조하지 않으므로 `predict(단독 행) == predict(전체)[i]`가 자동으로 성립한다.

투수 ID로 배정하는 방식은 쓰지 않는다. 신규 투수에서 무너지고 행 독립성 방어도 복잡해진다.

## 1. 전체 구조

```
                     ┌─ δ_type      (프로파일 기반, 커버리지 ~100%)
p_base ──logit──── + │                                              ──sigmoid──> p_k
                     └─ δ_pitcher   (개인 절편, 커버리지 77.45%)

                        w_p = n_p/(n_p+λ)
                        δ_total = (1-w_p)·δ_type + w_p·δ_pitcher

성분 k ∈ {m, r, o, mr} 각각에 위 계층을 적용

P(success) = 1 − [ p_m + p_r − p_mr + p_o ]
```

**표본이 많은 투수는 자기 절편, 적은 투수는 유형 절편.** 교과서적 계층 수축이고, 사용자가 말한 "개인화가 어려운 투수만 따로 모아 유형화"를 하드 분기 없이 연속적으로 구현한다.

### 기대값을 미리 계산해둔다

| 계층 | 커버리지 | 비고 |
|---|---:|---|
| δ_pitcher (누적 200구) | **77.45%** | 나머지 22.55%는 0 |
| δ_type | **~100%** | `n=0` 792행만 prior fallback |
| 개인화 불가 구간 | 22.55% | 그중 cold start 19.86% |

**유형 계층이 개인 계층보다 넓다.** 개인화의 증분은 22.55% 구간에 몰려 있으므로 그 구간에서 Brier를 x만큼 줄여도 전체 이득은 0.2255x다. 반대로 유형 계층은 전 구간에 걸린다.

## 2. 단계별 실험

### D1 — 투수 절편 residual (스크립트 완성, 실행 대기)

[`src/p3_pitcher_offset.py`](src/p3_pitcher_offset.py)

```
δ_p = (r_p / v_p) · n_p/(n_p+λ) · scale
```
- `r_p` = 순방향 체인 OOF 잔차 가중평균, `v_p` = p(1−p) 가중평균
- 그리드: T ∈ {100, 200, 500} × λ ∈ {50…2000} × scale ∈ {0.25…1.0} × half_life ∈ {1, 2, ∞}
- 선택 2022 전체 BSS, 부호 확인 2023, 게이트 2024 1회

> **중단 조건**: 2024 전체 ΔBSS가 쌍대 기준 미달이면 D3(계층 결합)의 개인 항을 빼고 유형 항만 간다. D1은 **싸고 D 전체의 방향을 정한다.**
>
> **가장 유력한 실패**: `asof_pitcher_success_rate` + prior 200 smoothing이 이미 절편을 흡수. 그러면 δ_p ≈ 0이 나온다.

---

### D2 — 투수 유형화

#### D2a 프로파일 벡터 (17차원, 전부 제공 컬럼)

| 묶음 | 컬럼 |
|---|---|
| 실패 구성 5 | `success` / `reverse` / `middle` / `ball` / `strike` rate |
| 구종 구성 3 | `fastball` / `breaking` / `offspeed` rate |
| 최근 폼 6 | `prev1/3/5_game_success_rate`, `prev1/3/5_game_middle_rate` |
| 표본량 1 | `log1p(asof_pitcher_n)` |
| 파생 2 | `ball − strike` gap, `prev1 − prev5` 추세 |

**표본량 수축을 프로파일 자체에 건다.** `n`이 작은 행의 rate는 노이즈다. 각 rate를 `(n·rate + λ_prof·prior)/(n + λ_prof)`로 수축한 뒤 클러스터링한다. `λ_prof ∈ {50, 200, 500}`.

**표준화는 학습 fold에서만 fit한다.**

#### D2b 유형 생성 4안 — 하나만 고르지 않고 전부 잰다

| 안 | 방법 | 근거 |
|---|---|---|
| **C1** | KMeans hard, K ∈ {3,4,6,8,12}, 20-seed 평균 | 기존 reverse 클러스터에서 검증된 방식 |
| **C2** | GMM soft assignment, 가중 residual | "hard cluster보다 soft residual이 안정적" (README §7.7) |
| **C3** | **클러스터 없이 프로파일 벡터로 residual GBDT** | 이산화 손실이 없다. **가장 유력** |
| C4 | 프로파일을 base 모델 피처로 직접 추가 | residual 계층 없이. 대조군 |

좌우 분리(`pitcher_hand`별) 여부도 축으로 넣는다. 기존 타자 클러스터가 좌 K=4 / 우 K=6으로 분리했다.

> **C3가 가장 유력한 이유**: "유형"은 결국 프로파일 → 잔차의 함수다. 클러스터는 그 함수를 계단으로 근사하는 것이고, GBDT는 직접 근사한다. C1/C2는 해석용·비교군으로 둔다.

#### D2c 유형 residual

```
δ_type = f(profile) · scale        # C3면 f = GBDT, C1/C2면 lookup
```
학습은 **순방향 체인 OOF 잔차** 위에서 한다 (D1과 동일 재료). in-sample 잔차를 쓰면 0으로 수축한다.

---

### D3 — 계층 결합

```
w_p     = n_p / (n_p + λ_h)
δ_total = (1 − w_p)·δ_type + w_p·δ_pitcher
```

- `λ_h` ∈ {100, 300, 1000, 3000} — 개인/유형 전환점
- 대조군: `δ_type`만 / `δ_pitcher`만 / 단순합 `δ_type + δ_pitcher`
- **저투구 구간만 따로 지표를 낸다.** `asof_pitcher_n` 구간별 ΔBSS를 반드시 분해해 본다. 이 계층이 노리는 곳이 거기다

---

### D4 — 최근 경기 정보 강화 (피처 수준)

"이전 경기 투구 정보를 인풋에 잘 넣는" 쪽. 6개 원본 컬럼은 이미 들어 있으니 **파생만** 만든다.

| 묶음 | 피처 |
|---|---|
| 추세 | `prev1−prev3`, `prev3−prev5`, 세 점 선형기울기 |
| 변동성 | `std(prev1,3,5)`, `range`, `|prev1−prev5|` |
| 누적 대비 | `prev_k − cumulative` (성공·middle 각 3개) — 하네스에 이미 있음 |
| 신뢰도 가중 | `prev_k × reliability(n)` |
| 결측 패턴 | 6개 중 결측 개수, 전부 결측 플래그 (1.98%) |
| **실패 방향** | `prev_k_middle − (1 − prev_k_success)` → 최근 실패가 middle 때문인지 아닌지 |
| **커리어 대비 최근** | `prev1_middle / asof_middle_rate` (비율, 0 나눔 방지) |

**`실패 방향`이 이번에 새로 의미가 생긴 항목이다.** 최근 폼은 `success`와 `middle`만 주어지는데, 그 둘의 차이가 "최근 실패가 가운데 몰림인가 아닌가"를 알려준다. 성분 분해와 직접 연결된다.

- 검증: 피처 묶음 단위 ablation. 한 번에 하나씩
- 채택: 2022·2024 전체 BSS 쌍대 기준 통과

---

### D5 — 성분 × 개인화 교차 (E1a 후속)

E1a에서 `middle`–`reverse` 의존이 가장 강한 축이 **`pitcher_id`** 였다 (246명 중 134명이 |φ|>0.03, lift 0.417~2.568). 그리고 E1b는 현재 피처가 그 의존을 전혀 설명 못 한다고 말한다 (잔차 상관 ≈ raw 상관).

→ **`p_mr` 모델에 프로파일·유형을 넣으면 그 자리가 채워진다.**

| 실험 | 내용 |
|---|---|
| D5a | `p_mr`에만 프로파일 벡터 추가, 나머지 성분 동일 |
| D5b | 네 성분 전부에 δ_type 적용 |
| D5c | 성분별로 λ·scale을 따로 튜닝 (난이도가 다르다) |

D5a가 싸고 진단적이다. 잔차 상관이 −0.066에서 얼마나 0으로 가는지가 직접 지표다.

## 3. 실행 순서와 중단 조건

| # | 실험 | 비용 | 선행 | 중단 조건 |
|---|---|---|---|---|
| 1 | **D1** 투수 절편 | 실행만 | — | 미달 → 개인 항 포기, D2로 |
| 2 | **D2a+C3** 프로파일 residual GBDT | 1시간 | — | 미달 → D2b 나머지 안 봄 |
| 3 | **D4** 최근 폼 파생 ablation | 2시간 | — | 묶음별 개별 판정 |
| 4 | **D3** 계층 결합 | 1시간 | D1 or D2 통과 | 둘 다 미달이면 생략 |
| 5 | **D5a** `p_mr` 프로파일 | 1시간 | P7 결과 | 잔차 상관 안 줄면 중단 |
| 6 | D2b C1/C2 클러스터 | 2시간 | C3 통과 | 해석·비교용 |
| 7 | D5b/D5c 성분별 확장 | 반나절 | D5a 통과 | |

**1·2·3은 서로 독립이라 순서 무관하고 병렬 가능하다.** GPU에서 각 fit이 3~4초라 전부 합쳐도 반나절이다.

## 4. 판정 규약 (P7에서 교정한 내용 반영)

**지표는 전체 BSS 하나.** R/F는 원인 파악용.

| 분모 | 정의 | 용도 |
|---|---|---|
| `σ_abs` | 절대 BSS의 시드 산포 | 독립 구성 비교. **차이 판정에는 쓰지 않는다** |
| `σ_pair` | 시드별 ΔBSS의 산포 | 다시 돌리면 뒤집히나 |
| **`SE_row`** | 행별 `(p_old−y)²−(p_new−y)²` 평균의 표준오차 | **다른 25만 행으로 전이되나** ← 제출 판단 |

- 선택은 **2022 전체 BSS**에서만, 2023은 **부호 확인만** (F 붕괴로 −16,022이라 게이트 부적합), 2024는 **1회 게이트**
- 문턱을 유의수준보다 높게 두는 근거는 노이즈가 아니라 **다중비교**다. 변형을 N개 보면 마진도 N에 맞춰 올린다
- `asof_pitcher_n` 구간별 ΔBSS를 **항상 분해**해서 기록한다. 계층 설계가 노리는 구간에서 실제로 개선되는지가 설계 검증이다

## 5. 규정 체크 (설계 단계에서 미리)

| 항목 | 상태 |
|---|---|
| 유형 배정이 test 행 간 참조를 하는가 | **아니오.** 행 자기 `asof` 벡터로 배정 |
| 클러스터 중심·표준화가 검증 시즌을 보는가 | **아니오.** 학습 fold에서만 fit |
| 성분 라벨이 추론 경로에 들어가는가 | **아니오.** 학습 전용, `script.py`에 없음 |
| δ 산출이 검증 시즌 라벨을 쓰는가 | **아니오.** 순방향 체인 OOF만 |
| 신규 투수 fallback | δ_pitcher=0, δ_type은 prior 수축 프로파일로 배정 |

행 독립성 기계 검증(`predict(단독 행) == predict(전체)[i]`)을 **D3 완성 시점에 한 번** 돌린다.
