## 1. 피처 분류

### A — test 데이터에 그대로 있는 피처 (원본)

| 하위 | 내용 | 현황 |
|---|---|---|
| **A1 상황** | `inning`, `balls/strikes/outs_before`, 주자, 점수차, `li`, 승리확률, `game_month/dayofweek`, `top_bottom`, `game_type` | 24개, 전부 사용 중 |
| **A2 as-of 누적** | `asof_pitcher_*` (n, success/reverse/middle/ball/strike rate, prev1/3/5 game, pitchmix), `asof_batter_*` | 19개, 전부 사용 중 |
| **A3 식별자** | `pitcher_id`, `batter_id`, `*_team_id`, `pitcher_hand`, `batter_hand` | 사용 중 |

**제약**: 없음. 행에 그대로 있으므로 행 독립성 자동 충족.

> **Phase-0 실측**: `asof_*` 19개가 AUC의 거의 전부를 만든다 (0.5202 → 0.5437). ID를 더 줘도 **+0.0009**. **A 계열 원본만으로는 AUC ~0.544가 천장이다.**

### B — A에서 파생하는 피처

| 하위 | 정의 | 행 독립성 | 위험 |
|---|---|---|---|
| **B1 단일 행 변환** | 한 행 안에서 계산: 비, 차, 곱, 버킷, 상호작용 | 자동 충족 | 없음 |
| **B2 학습 집계 룩업** | 학습 데이터에서 만든 정적 테이블을 키로 조인 (EB 플래툰, 계층 차감) | 조인이 단건이면 충족 | **셀 희소성 → 자기 라벨 누수** |
| **B3 라벨 유래 테이블** | 성분 라벨(`m/r/mr/ob/oz`)로 만든 테이블 | 〃 | **중복 + 누수 이중 위험** |

**B1 검증된 예**: 2차 상호작용 12열 (V71 C4 → `submit_035`)
**B2 검증된 예**: 투수 플래툰 +13.75, 카운트 플래툰 +8.44, 이닝 플래툰 +2.98
**B3 검증된 예**: 타자 성분별 플래툰 +2.44 / **기각 예**: 투수 성분별 플래툰 (V8·V37)

### C — TrackMan 기반 투수 ID 임베딩

| 하위 | 내용 | 현황 |
|---|---|---|
| **C1 물리 요약** | `tm500_*` 47개 (속도/회전/무브먼트/릴리스의 latest·recent 평균·표준편차) | **base가 이미 98개 보유** |
| **C2 조건부 반응** | Tier E — (구종군 × 카운트버킷 × 타자손) 셀의 사용률·물리 잔차 → SVD 12차원 | 산출물 있음 |
| **C3 파생** | 군집 ID/소속확률, 커널 이웃, 임베딩 좌표 | 여러 형태 시도됨 |

**전부 `(pitcher_id, season)` 단위 정적 룩업**이다. 추론 시 `pitcher_id` 단건 조인이라 행 독립성이 유지된다.

## 2. 인수 검증 — 실험 전에 반드시 통과

새 피처는 **실험에 넣기 전에** 아래를 기계로 통과해야 한다. 실패한 항목이 있으면 그 피처는 보류한다.

### G1. 행 독립성 (전 계열 공통)

```
피처값(행 i) 이 다른 test 행에 의존하지 않는가
  B1  단일 행 계산이면 자동 통과
  B2/B3/C  키(pitcher_id 등)로 조인하는 정적 테이블이면 통과
  금지: test 행끼리의 groupby / rolling / cumsum
```

`p15_smoke024.py` 6번 항목(부분 실행 == 전체 실행)이 최종 방어선이다.

### G2. 시간 인과 (as-of)

```
시즌 S 행의 피처는 season < S 정보만 써야 한다
  A2  대회가 제공한 asof_* 는 이미 충족
  B2/B3  fold 마다 학습 시즌만으로 테이블 재생성
  C   TrackMan 은 strict as-of (규칙 N1: 증거 시즌 2022 이후만)
```

### G3. 셀 크기 (B2·B3·C3) — **가장 자주 터진 곳**

정적 테이블은 셀이 작아질수록 자기 라벨을 흘린다. **네 번 관측했다.**

| 사례 | 성분단독 붕괴 |
|---|---|
| V1 정적 '레벨' | 705.7 → 187.5 |
| V37 성분 테이블 1겹 | 743.8 → 507.8 |
| V35 투수×타자 개별 | 745.9 → 259.1 |
| V59 outcome 커널 | 744.1 → 533.4 |

**기준**: 셀 중앙 크기와 `K`(EB 수축)로 **한 행의 기여분 = 1/(n+K)** 를 계산해 보고한다.

```
현행 투수 x 타자손:  셀 1,413개, 중앙 393행, K=300 -> 기여 0.144%   (안전)
투수 x 타자 개별:    셀 26,355개, 중앙 13행                          (붕괴)
```

**중앙 셀 기여가 1%를 넘으면 경고**, 3%를 넘으면 보류.

### G4. 계층 차감의 두 조건 (B2·B3)

상호작용 테이블이면:

- **ㄱ. 중복이 실재하는가** — 빼려는 주효과가 이미 모델에 있는가. 없으면 차감이 신호를 지운다.
- **ㄴ. 두 항이 같은 단위인가** — 다르면 환산 계수를 추정해야 하고, 그 계수가 틀린 만큼 잡음이 들어간다 (V43: 단독 −35.79).

> V19가 잘 된 이유가 정확히 이 둘이다 — 카운트 주효과가 `balls`/`strikes`에 이미 있었고, 두 항이 모두 성공률 EB라 계수가 1이었다.

### G5. base와의 중복 (C 계열 특히)

**base가 이미 tm500 98개를 쓴다.** C1을 그대로 넣으면 단독은 올라도 상관이 같이 올라 결합이 손해다.

```
V66 P1: 단독 +21.04 (2023)  그런데 상관 0.8889 -> 0.8905,  결합 -0.30
```

**C 계열은 반드시 base 상관 변화를 함께 보고한다.**

### G6. 커버리지

결측률과 fold별 커버리지를 보고한다. 학습 커버리지와 검증 커버리지가 크게 다르면(예: Tier E는 학습 21% vs 검증 59%) 분포 불일치를 명시한다.

## 3. 판정 기준

> **2026-08-18 개정.** V77·V79·V84 로 fold 의 성격이 밝혀지면서 바뀌었다.
> 이전 판(“fold 2023·2024 양쪽에서”)은 fold 마다 무엇을 재고 있는지 모르고 쓴 것이다.

### 3-0. 어느 fold 를 믿는가 — 먼저 이것부터

| fold | 상태 | 쓰는 법 |
|---|---|---|
| **2024** | **신뢰 가능** | **결정 fold.** 가중 2 |
| 2023 | 오프셋 교란 | 보조. 가중 1. **`bss_centered` 로 본다** |
| **2022** | **역신호** | **쓰지 않는다** |

**2022 를 빼는 이유** (V84). 방법 17개의 순위 상관이

| 계열 | 2022→2023 | 2023→2024 | **2022→2024** |
|---|---:|---:|---:|
| xgboost | −0.632 | +0.385 | **−0.537** |
| catboost | +0.656 | −0.241 | **−0.645** |

**두 계열 모두 2022→2024 가 음수다.** 2022 에서 잘하면 2024 에서 못한다.
가중을 낮추는 것으로 부족하다 — 1/7 만 줘도 역신호가 섞인다.
실측: 단순평균으로 고르면 CatBoost 에서 “보정 안 함”을 골라 **−37.77** 을 물었다.

**2023 을 조심하는 이유** (V77). base 예측 평균이 실제보다 +0.0224 높아
`bss_raw` 가 −140.20 인데 오프셋만 제거하면 +60.68 이다. 손실 200.88 이 전부 오프셋이다.
그래서 이 fold 의 ΔBSS 는 **신호가 아니라 두 어긋난 평균의 상쇄량** 을 잰다.
V69·V70·V75 가 전부 “2023 에서 크게 이기고 2024 에서 진다” 였던 이유가 이것이다.

> **집계식**: `점수 = (1 × fold2023 + 2 × fold2024) / 3`
> 그리고 **fold 2024 가 음수면 2023 이 아무리 좋아도 기각한다.**

### 3-1. 채택 조건

**fold 2024 에서 아래 셋이 함께, fold 2023 에서 반대 방향이 아닐 것**:

| 지표 | 방향 | 의미 |
|---|---|---|
| 성분단독 BSS | ↑ | 피처가 실제로 예측을 개선했는가 |
| **base 와의 logit 상관** | ↓ | 결합 가치가 있는가 (V65) |
| 결합 ΔBSS | ↑ | 최종 목적함수 |
| **`bss_centered` ΔBSS** | ↑ | **평균 정렬이 아니라 신호로 번 것인가** |

**셋이 어긋나면 상관을 우선한다.** V65·V66 이 정확도와 결합 가치가 반대로 움직이는 것을
두 방향에서 보여줬다. 단, **정확도가 절벽으로 떨어지면 예외다** — V70 은 상관 0.6032
(역대 최저)를 얻고도 단독이 653 떨어져 −76.56 이었다.

`bss_centered` 는 예측 평균을 실제 평균에 맞춘 뒤의 BSS 다 (`harness.metrics()` 제공).
`bss_raw − bss_centered` 가 **평균 정렬로 번 점수** 이고, 그건 다른 fold·Public 으로
따라가지 않는다. V79 에서 블렌드가 raw +39.95 / centered +41.88 로 나온 것이
“성분 분해의 이득은 진짜 신호” 라는 근거였다.

### 3-2. 무엇 위에서 재는가 — V83 이 남긴 함정

**그 모델 계열의 최선 전역 offset 위에서 재야 한다.**

같은 세그먼트 보정이 CatBoost 를 나쁜 기준선(`all_d100`, 2023=5.12) 위에서 재면 **+10.20**,
최선 기준선(`last3_d075`, 2023=60.36) 위에서 재면 **−0.38 ~ +0.54** 다.
나쁜 기준선 위의 이득은 전역 예보의 부족분을 대신 메운 것이지 새 정보가 아니다.

- xgboost 최선 전역: `all_d100`
- catboost 최선 전역: `last3_d075`
- 계열마다 다르므로 새 계열을 쓰면 먼저 전역 스윕부터 한다

### 3-3. 하이퍼파라미터가 붙는 경우

수축 계수 K, 적용 강도 W 같은 것이 붙으면 **한 점이 아니라 넓은 구간에서** 통과해야 한다.
좁은 구간에서만 이기면 그건 fold 를 보고 그 값을 고르는 것이다.

실례 — V87 이 통과한 모습 (추세×신뢰, 두 계열 · 여섯 점 연속 양수):

| W | xgb 2023 Δ | xgb 2024 Δ | cat 2023 Δ | cat 2024 Δ |
|---|---:|---:|---:|---:|
| 0.05 | +1.45 | +1.57 | +0.35 | +1.53 |
| 0.20 | +4.74 | +3.54 | +0.42 | +4.00 |
| 0.30 | +6.06 | +2.59 | −0.37 | +3.86 |

### 3-4. 크기 해석 — Public 실측 기반

| 변경 | 내부 ΔBSS | Public Δ |
|---|---:|---:|
| 구간 가중치 | +2.46 | **+15** |
| Tier E | +2.47 | **−5.86** |
| 짧은 등판 | +0.63 / −1.74 | **+4** |
| 2차 상호작용 | +3.50 | **+2** |

> **내부 델타는 Public 델타를 예측하지 못한다.** 방향 선택에는 쓰되,
> **제출 후보를 하나로 좁히는 데는 쓰지 않는다.** 후보가 여럿이면 여러 개를 제출해 확인한다.
> 그리고 **내부 +3 미만은 제출본 교체 근거로 쓰지 않는다** (V61).

### 3-5. 시드 잡음 (실측)

| | sd | 범위 폭 |
|---|---:|---:|
| fold 2024 성분단독 | 1.37 | 4.32 |
| fold 2023 성분단독 | 4.87 | 13.41 |

**단일 fold 선별은 네 번 뒤집혔다** (V23·V38·V47·V64).
그래서 fold 2023 을 버리지 않고 보조로 남긴다 — 다만 `bss_centered` 로 본다.

## 4. 새 피처를 어디에 넣는가

현재 파이프라인의 삽입 지점:

```
[A 원본] ──┐
[B1 파생] ─┤
[B2 룩업] ─┼─→ 111열 피처 행렬 ─→ 5성분 모델 (XGB+CatBoost × 8시드)
[B3 라벨] ─┤                          ↓
[C 임베딩] ┘                    포함-배제 합성 ─→ 성분 라인
                                                    ↓
                              prediction = w(구간) × 성분 + (1−w) × base
```

**코드 위치**: `component_features.py`의 `build()` 반환 직전에 열을 추가하면 학습·추론 양쪽에 동시 반영된다. 제출 패키지에서는 `script.py`의 `component_features()`에 같은 코드를 주입한다(빌드 스크립트가 수행).

## 5. 실행 순서

### S0. 인수 검증 (5분, CPU)

```bash
python cowork/sj/claude/src/v76_feature_intake.py --spec <피처정의> --gate-only
```

G1~G6을 기계로 검사하고 셀 크기·커버리지·상관을 보고한다. **실패 항목이 있으면 여기서 멈춘다.**

### S1. 단독 스크리닝 (fold 2024, ~5분/arm)

새 피처를 그룹 단위로 켜고 끄며 fold 2024에서 방향을 본다.
**주의**: 단일 fold 선별은 방향 확인용이다. 여기서 고른 것을 그대로 채택하지 않는다.

### S2. 확인 — fold 2024 결정 + fold 2023 보조 (~10분/arm)

S1에서 유망한 것만 fold 2023·2024 전체 구성으로 확인. **§3-1의 채택 조건을 전부 본다.**
**fold 2022 는 돌리지 않는다** (§3-0). 점수는 `(1×2023 + 2×2024)/3`,
**fold 2024 가 음수면 기각** 이다.

### S3. 2차 확장 (~50분)
