## 0. 결론부터

이 문제에서 컴퓨팅을 더 쓴다는 것은 **더 큰 모델을 학습하는 것이 아니라 더 많이 검증하는 것**이다.

P0 진단이 이유를 확정했다.

| 흔한 "컴퓨팅 많이 쓰기" | 이 문제에서의 실측 | 판정 |
|---|---|---|
| 모델을 크게 | 32→128 leaves: 780.80 → 726.37 | 이미 실패 |
| seed를 많이 | 20-leaf 5-seed는 seed 0 단독보다 나쁨, F24 포화 | 이미 실패 |
| 데이터를 늘리기 / 증강 | 학습 행 50%→100%에서 BSS +9.7 (1.7%) | 포화 |
| 하이퍼 탐색을 더 | Optuna 25회 재탐색에서 기존 trial93 유지 | 포화 |
| 피처를 더 | 구종별 TrackMan 확장 760.71~764.94 (compact 769.69보다 낮음) | 역효과 |
| **검증을 더** | 구조 선택의 F23/F24 spearman **0.06** | **여기가 비어 있다** |

현재 최대 리스크는 성능 부족이 아니라 **선택 과적합**이다. 상위 8개 후보가 ΔBrier 2e-6 ~ 2e-5 구간에서 경쟁하는데, 구조 선택의 fold 간 순위 상관이 0.06이다. 즉 **컴퓨팅을 후보를 더 만드는 데 쓰면 상황이 악화되고, 후보를 더 엄격하게 걸러내는 데 쓰면 개선된다.**

## 1. 최우선 — 블록 부트스트랩 후보 평가 (embarrassingly parallel)

### 문제

현재 후보 판정은 fold별 단일 ΔBrier 스칼라 하나다. `submit_013`(812.704)과 공동 SVD 공격형(815.083)의 차이는 ΔBrier 약 **5.9e-6**인데, 이 차이의 불확실성이 측정된 적이 없다.

### 방법

fold 안에서 블록을 잡아 재표집한다. 행 단위 부트스트랩은 같은 투수·같은 경기의 상관을 무시해 표준오차를 과소평가하므로 **블록 단위**로 한다.

```python
# 블록 정의 3종을 모두 돌려 표준오차의 하한/상한을 잡는다
BLOCKS = {
  'month'   : df.game_month,                      # 6~7 블록  (시간 상관)
  'pitcher' : df.pitcher_id,                      # 391 블록  (선수 상관)  <- 가장 보수적
  'pit_mon' : df.pitcher_id * 100 + df.game_month # 교차
}
# 후보 쌍 (p1, p2) 에 대해
for b in range(2000):
    ids = rng.choice(unique_blocks, size=len(unique_blocks), replace=True)
    idx = concat(block_index[i] for i in ids)
    delta[b] = brier(p1[idx], y[idx]) - brier(p2[idx], y[idx])
ci = np.percentile(delta, [2.5, 97.5])
```

### 비용과 산출

- 후보 8개 → 쌍 28개 × 블록정의 3종 × 2,000 부트스트랩 = 168,000회 Brier 계산. 253,507행 벡터 연산이므로 **수십 분** (병렬화하면 수 분).
- 산출: **후보 순위표에 95% CI를 붙인 표.** CI가 겹치는 후보들은 "점수로 구분 불가"로 명시하고, 그 그룹 안에서는 구조적 안정성(R 양 fold, F 의존율, 커버리지)으로 정한다.

### 왜 최우선인가

이 표 하나가 **남은 2주 동안 무엇을 쫓을지를 결정한다.** CI가 ±20 BSS라면 "+27 개선"을 쫓는 것은 의미가 있지만 "+0.7 개선"을 쫓는 것은 노이즈 추적이다. 지금은 어느 쪽인지 모른다.

## 2. nested 선택 — F24를 선택에서 빼기

### 문제

현재 모든 구조·강도 탐색이 F24를 보고 이뤄지므로 **보고되는 F24 점수는 낙관적**이다. 그리고 P0-1에서 구조 선택은 fold 간 전이가 안 된다(spearman 0.06)는 것이 확인됐다.

### 방법

```
선택 단계 : F22 + F23 만으로 구조·강도를 고른다  (목적: min(ΔBrier22, ΔBrier23) 또는 robust_objective)
확인 단계 : 고른 후보를 F24 에서 딱 한 번 평가한다
추가 fold : 2024 를 월 블록으로 쪼개 pseudo-fold 6개를 만들어 선택 단계에 편입
```

2024를 전반기/후반기로 쪼개거나 월 블록 6개로 쪼개면 선택용 fold를 늘릴 수 있다. 각 블록은 40,000행 규모이므로 개별 ΔBrier 추정은 시끄럽지만, **6개 블록에서 부호가 일치하는지**를 보는 것은 유효한 안정성 지표다.

### 비용

기존 탐색을 그대로 다시 돌리는 것이므로 계산량은 기존 탐색의 1~2배. `joint_svd_cluster_grid` 5,670개 + `deep_pitcher_cluster_grid` 8,232개 = 약 14,000 구성. 각 구성이 Ridge 적합 + 벡터 연산 수준이면 **수 시간**, XGB 재학습이 필요하면 GPU 또는 다중 코어 필요.

### 산출

"F22·F23에서 고른 최적 구조"와 "F24에서 고른 최적 구조"가 얼마나 다른지. P0-1의 Jaccard 0.03을 보면 크게 다를 것이고, 그 차이가 곧 현재 F24 점수의 낙관 편향 크기다.

## 3. Tier E 전수 탐색 — 여기는 후보를 더 만들어도 된다

§1·§2와 달리 **아직 탐색되지 않은 공간**이므로 컴퓨팅을 후보 생성에 써도 된다.

O2 상한 917.7 vs 현재 815.08 → +100 여지가 있고, 조건부 축의 설계 공간은 넓다.

| 축 | 후보 |
|---|---|
| 조건 변수 조합 | `{볼카운트, 타자손, 아웃, 주자, 이닝구간, li 구간}`의 부분집합 — 2⁶ = 64 |
| 집계 대상 | 구종 사용률 / 구속 rz / IVB rz / 릴리스 잔차 SD / reverse율 / middle율 — 6 |
| 평활 강도 | EB `m0 ∈ {50, 100, 200, 500, 1000}` — 5 |
| 압축 차원 | SVD/NMF `dim ∈ {4, 8, 16, 32}` — 4 |
| 주입 형태 | 잔차 / 커널 평활 / expert — 3 |

전수 조합은 64 × 6 × 5 × 4 × 3 = 23,040개다. 전부 돌릴 필요는 없고, **조건 변수 조합(64) × 집계 대상(6) = 384개를 1차 스크리닝**한 뒤 상위만 확장하는 계단식이 맞다.

- 1차 스크리닝은 XGB 재학습 없이 **잔차 상관**으로 한다: 후보 피처와 현재 모델의 시간 OOF 잔차 사이의 편상관. 이것만으로 384개를 수 분에 걸러낼 수 있다.
- 살아남은 20~30개만 XGB / Ridge correction으로 정식 평가.

**중요**: 384개를 스크리닝하는 것 자체가 다중검정이다. **F22·F23으로 스크리닝하고 F24는 최종 확인용으로만** 쓴다(§2).

## 4. 모델 다양성 확장 — 유일하게 반복 성공한 축

팀의 실증에서 **일관되게 이득을 낸 것은 "서로 다른 잔차를 가진 모델의 혼합"**이었다.

| 근거 |
|---|
| 시간 OOF 앙상블: 784.56 → 789.67 |
| 공동 SVD가 기존 correction과 상관 **0.09** → 815.08로 이득 |
| 멀티뷰 SVD는 상관 0.887 → 가중치 0으로 수렴 (다양성이 없으면 무이득) |
| 24-leaf diverse expert 추가: 812.70 → 813.43 |

현재 앙상블 멤버는 xgboost / catboost / lightgbm 세 계열뿐이다. **상관이 낮은 멤버를 늘리는 것이 컴퓨팅을 쓰는 정당한 방향이다.**

| 후보 멤버 | 왜 잔차가 다를까 |
|---|---|
| **G 부분 분리 R 전용 모델** | P0-6에서 이미 +16.1 확인. 학습 표본이 다르므로 잔차가 다르다 |
| spline GLM / GAM (`asof_*`에 자연 스플라인) | 트리와 근본적으로 다른 함수 형태 → 부드러운 외삽. 드리프트에 강할 가능성 |
| Field-aware FM / FFM | 상호작용을 저차원 내적으로 표현 → 트리의 축평행 분할과 다름 |
| 소형 MLP (Tier E 피처 + `asof_*`) | F23에서 NN이 AUC 최고(0.531877)였던 전례 |
| Regularized Greedy Forest | 트리지만 정규화 방식이 달라 잔차 구조가 다름 |
| 분위 회귀 앙상블 / isotonic 스태킹 | 캘리브레이션 축의 다양성 |

**선정 규칙**: 새 멤버는 단독 성능이 낮아도 된다. 기준은 **기존 최고 예측과의 상관 < 0.95** 이고 **시간 OOF 스태킹에서 가중치 > 0.05** 를 받는 것이다. 상관 0.887이 가중치 0으로 수렴한 전례가 있으므로 0.95는 느슨한 상한이고, 실제로는 0.90 미만을 노려야 한다.

**비용**: 멤버당 학습 수 분 ~ 수십 분. 6개 후보 × 3 fold = 18회. 하루 안에 가능.

## 5. Tier E 조건부 프로파일의 안정성을 부트스트랩으로 검증

Tier E는 셀이 잘게 쪼개진다(`투수 × 시즌 × 볼카운트 × 타자손` = 8,492 셀, 셀당 median n=63). 이 추정치의 분산이 크므로 **평활 강도를 점수로 고르면 과적합한다.**

컴퓨팅을 쓰는 정당한 방법: **투수 단위 부트스트랩으로 프로파일 자체의 안정성을 재고, 안정적인 셀만 쓴다.**

```python
# 투수-시즌의 등판을 부트스트랩 재표집해 프로파일을 B회 재계산
# 각 셀의 부트스트랩 SD 를 신뢰도로 사용 -> 그 자체를 피처로 (또는 가중으로)
for b in range(200):
    resampled = resample_outings(tm_pitcher_season, rng)
    profile_b = build_tier_e(resampled)
profile_sd = profile_b.std(axis=0)          # 셀별 추정 불확실성
weight = 1 / (1 + profile_sd**2 / tau**2)   # 불확실한 셀을 자동 축소
```

이것은 EB 축소를 데이터에서 직접 추정하는 것과 같고, `m0` 그리드를 점수로 고르는 것보다 원리적으로 낫다(그리고 선택 과적합을 줄인다).

**비용**: 투수-시즌 1,391건 × 200 부트스트랩. TrackMan 1.79M 행 위에서 groupby 200회 → 수십 분.

```
# 실험 단위를 JSON 큐로 만들고 워커가 꺼내 쓴다 (기존 long_experiment_queue.json 패턴 재사용)

```

기존 `experiment/model_optimization/long_experiment_queue.json`(18KB)과 `.process.json` 패턴이 이미 있으므로 그걸 재사용하면 된다. 새로 만들 필요 없다.

**주의 하나**: 병렬로 후보를 대량 생산하면 **다중검정이 심해진다.** 큐에 넣은 후보 수 `K`를 기록하고, 최종 선택 시 Bonferroni 또는 Benjamini–Hochberg로 보정한 임계를 쓴다. 후보를 1,000개 만들었다면 "95% CI가 0을 안 포함" 기준은 이미 무의미하다 — `K=1000`이면 우연히 통과하는 후보가 50개 나온다. **§2의 nested 구조가 이 문제에 대한 실질적 방어선이다.**
