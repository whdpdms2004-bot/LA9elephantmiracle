## 2. 무엇을 만들었나

### 2-1. 핵심 아이디어 — 실패를 유형으로 분해한다

`control_success`를 직접 맞히는 대신, **어떻게 실패했는지**를 유형별로 예측하고 합친다.

```
M  middle    한가운데
R  reverse   반대 코스
O  OUTSIDE  := 실패 ∧ ¬M ∧ ¬R      (잔여로 정의)
             O 를 ball 로 다시 쪼갠다 -> ob, oz

P(실패) = P(M) + P(R) − P(M∩R) + P(ob) + P(oz)
P(성공) = 1 − P(실패)
```

추정 대상은 다섯: `m, r, mr, ob, oz`. 각각 XGBoost + CatBoost × 8시드 = 성분당 16모델, 총 80모델.

### 2-2. 라벨은 train.csv에서 복원한다

대회 데이터에 실패 유형 라벨은 없다. **누적 통계의 차분**으로 복원한다.

```
누적카운트(i) = asof_rate(i) × asof_pitcher_n(i)
label(i)      = 누적카운트(i+1) − 누적카운트(i) ∈ {0, 1}
```

투수별 `asof_pitcher_n` 순서로 정렬해 인접 차분. `success / middle / reverse / ball` 넷에 각각 적용.

| 검증 | 결과 |
|---|---|
| 복원 행 | 1,473,508 / 1,475,092 |
| 복원 불가 | 1,584 (첫 투구 NaN 792 + 마지막 투구 792) |
| `control_success`와 일치율 | **100.000000%** (불일치 0행) |
| 포함-배제 성립 | 불일치 **0행** |

> **주의**: `asof_*_rate`가 float32라 `rate × n`의 오차가 ~1e-3이다. **차분 전에 반올림**해야 한다. 안 하면 1/140만 행만 복원된다.

**라벨은 학습에만 쓴다.** 추론 경로에 유도 코드가 없어야 하고, 6단계 검증이 기계로 확인한다.

### 2-3. 최종 예측 구조

```
prediction = w(투구량 구간) × [성분 라인] + (1 − w) × [프로덕션 base]

w = [0.25, 0.25, 0.25, 0.30, 0.40]
    구간 = asof_pitcher_n < 100 / 500 / 2000 / 4000 / 그 이상
```

### 3-1. 계층 차감이 무엇인가 — 이 프로젝트 최대 발견

```
split(p, h, 축) = EB(투수, 타자손, 축) − EB(투수, 타자손)
```

**주효과를 빼는 것이 전부다.** 같은 구조의 피처가 차감 겹수만으로 50배 차이 났다.

| | 차감 | 결과 |
|---|---|---:|
| V8 | 리그평균만 (1겹) | **+0.16** |
| V19 | 리그평균 + 전역 카운트효과 (2겹) | **+8.44** |

1겹만 빼면 남는 신호의 대부분이 "카운트 자체의 효과"인데, 그건 이미 원본 피처(`balls`, `strikes`)에 있어 중복이다. **전역 효과까지 빼야** "이 투수가 이 카운트에서 남들보다 얼마나 다른가"라는 순수 상호작용만 남는다.

## 5. 확립된 원리 6가지

### ① 계층 차감에는 조건이 둘 있다

- **ㄱ. 중복이 실재해야 한다.** 차감은 '중복'을 고치지 '누수'를 고치지 못한다 (V37).
- **ㄴ. 두 항이 같은 단위여야 한다.** 단위가 다르면 환산 계수를 추정해야 하고, 그 계수가 틀린 만큼 잡음이 들어간다 (V43: 단독 −35.79).

V19가 잘 된 것은 둘 다 충족했기 때문이다 — 카운트 주효과가 `balls`/`strikes`에 이미 있었고, 두 항이 모두 성공률 EB라 계수가 정확히 1이었다.

### ② 정적 테이블은 셀이 작아질수록 자기 라벨을 흘린다

| | 성분단독 붕괴 | 무엇이 흘렸나 |
|---|---|---|
| V1 정적 '레벨' | 705.7 → 187.5 | 테이블 **값** |
| V37 성분 테이블 1겹 | 743.8 → 507.8 | 테이블 **값** |
| V35 투수×타자 개별 | 745.9 → 259.1 | 테이블 **값** |
| V59 outcome 커널 | 744.1 → 533.4 | **이웃을 고르는 기준** |

**값이 아니라 '선택 구조'로도 같은 붕괴가 난다.** 현행 축(투수×타자손)은 셀 중앙 393행이라 한 행 기여가 0.144%로 유계다.

### ③ 정확도가 비슷한 멤버들 사이에서는 비상관성이 결정한다

같은 111피처로 `control_success`를 직접 예측한 모델 vs 성분 분해 모델 (V65):

| | 단독 BSS | base 상관 | 결합 ΔBSS |
|---|---:|---:|---:|
| 직접 모델 | **751.20** | 0.8529 | +23.43 |
| 성분 분해 | 745.30 | **0.8219** | **+41.04** |

**단독은 직접이 낫고 결합은 분해가 압도한다.** 차이는 상관뿐이다. 성분 분해가 왜 되는지가 여기서 설명된다.

V66이 반대 방향으로 같은 원리를 확인했다 — TrackMan을 넣으니 단독 +21.04인데 상관도 0.8889→0.8905로 올라 **결합 −0.30**.

**단, "정확도가 비슷한"이 조건이다.** 처음엔 이 원리를 "정확도가 아니라 비상관성"이라고만 적었는데 V70이 반례를 냈다 — attention 피처로 축을 대체하니 base 상관 **0.6032**(역대 최저, 종전 V69의 0.7943)를 얻고도 결합 **−76.56**이었다. 단독이 748.44 → 95.83으로 653 떨어졌기 때문이다. 상관이 아무리 낮아도 정확도가 절벽으로 떨어지면 회복되지 않는다.

| V70 arm | 2024 단독 | base 상관 | 결합 ΔBSS |
|---|---:|---:|---:|
| B0 기준 | 748.44 | 0.8203 | +43.90 |
| B1 attention 추가 | 249.90 | 0.6250 | −2.26 |
| B2 attention 대체 | 95.83 | **0.6032** | **−76.56** |

남는 사실은 있다 — attention은 정말로 다른 것을 본다. 정확도를 안 깎으면서 그 비상관성을 얻는 설계가 있다면 가장 값진 멤버가 된다. 아직 찾지 못했다.

### ④ 전문화와 수축은 같은 트레이드오프의 양끝

| | 정상 연도 (2022/2024) | 레짐 변화 (2023) |
|---|---:|---:|
| 로짓 수축 `scale 0.70` (V34) | −40.50 / −19.47 | **+17.82** |
| 성분 세분화 `m→mb,mz` (V38) | +1.53 / +2.74 | **−7.07** |

세 fold 규칙이 양쪽을 다 걸러낸다. 그게 규칙의 목적이다.

### ⑤ 거를 행은 버리지 말고 가중치를 낮춘다

45조합 스윕(V63)에서 **제거 arm만** 제외 비율에 따라 단조 악화했다.

```
V500_drop  20.78% 제거  ->  ΔBSS −7.33,  단독 −89.53
S0.5_w0.5  제거 0%      ->  ΔBSS +1.97,  단독 +7.26
```

학습 행을 절반으로 줄이는 비용이 **−4.39**로 측정돼 있다(V9). V10에서 F행을 버리는 대신 0.20을 준 게 +4.07이었던 것과 같은 구조다.

### ⑥ 기저율 이질성은 모델을 쪼갤 근거가 아니다

볼카운트별 실패 구성이 크게 다르다 — `oz`가 3-0에서 0.003, 1-2에서 0.048로 **16배**. 그런데 카운트로 모델을 쪼개니 단조 악화했다 (V50).

```
전역 5모델      단독 747.44
카운트 3군 15모델  695.07  (−52.37)
카운트 12셀 60모델 432.10  (−315.34)
```

손해 크기가 **데이터 손실만으로 설명된다** — 전문화 이득이 0이다. 원본에 `balls`/`strikes`가 이미 있고 계층 차감 스플릿까지 있어서, 쪼개는 건 표현을 개선하지 못하면서 투수 정체성을 배울 데이터만 줄인다.

> **쪼개는 것이 값을 하려면 기저율이 아니라 *함수 관계*가 세그먼트마다 달라야 한다.**

| 030 → 032 구간 가중치 | +2.46 | **+15** |
| 032 → 033 Tier E | +2.47 | **−5.86** |

| 032 → 035 2차 상호작용 | **+3.50** | **+2** |

**내부 델타와 Public 델타 사이에 관계가 없다.**

- 내부적으로 거의 같은 크기의 두 변경이 Public에서 **+15와 −5.86**으로 갈렸다.
- **가장 강한 내부 근거**(035: 두 fold 양수, 단독+상관+ΔBSS 세 신호 정렬, +3.50)가 **가장 작은 이득**(+2)을 냈다.
- 내부에서 **재현 실패해 기각했던 항목**(034)이 **최고점**(+4)이다.

### 실무 함의

> **내부 지표는 "어느 방향이 유망한가"를 고르는 데는 쓸 수 있어도, "어느 패키지를 낼까"를 정하는 데는 못 쓴다.**
>
> 제출 후보가 여러 개면 내부 순위로 하나만 고르지 말고 **여러 개를 내서 Public으로 확인**해야 한다.
