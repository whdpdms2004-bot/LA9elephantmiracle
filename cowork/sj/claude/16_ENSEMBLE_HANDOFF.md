## ⚠️ 가중치 산출 방식 — 합의가 필요합니다

팀통합 §5-3은 최적 가중치를 이렇게 구합니다.

```
A = (BSS × U + V) / 2     ← BSS는 각자의 Public 점수
w* = M⁻¹A                  ← M은 예측 간 공분산
```

**이 방식 그대로는 규정 위반 소지가 큽니다.**

| 항목 | 문제 | 근거 |
|---|---|---|
| `A`를 **리더보드 점수에서 역산** | Public BSS는 평가 데이터의 실제 정답으로 계산된 값이다. 이걸로 가중치를 맞추면 평가 데이터 라벨에 fitting하는 것 | `RULES.md` §2 · §9 · §10-A |
| `M`을 **test 예측으로 계산** | test 행을 가로지르는 공분산 = 평가 데이터 분포 이용 | `RULES.md` §2 |

가중치가 전 행에 동일한 상수라는 점은 면책이 되지 않습니다. 문제는 **값의 출처**입니다.

### 대안 — 수식은 그대로, 출처만 바꿉니다

`A`와 `M`을 **홀드아웃 2024에서 실제 라벨로** 계산합니다. 닫힌 형태 `w* = M⁻¹A`는 동일하고 리더보드를 한 번도 경유하지 않습니다.

```python
D = np.column_stack([p_i - r for p_i in val_preds])   # r = 학습 데이터 기반 상수
M = D.T @ D / len(D)                                   # 검증 예측만으로 계산
A = D.T @ (y_val - r) / len(D)                         # 검증 정답 사용
w = np.linalg.solve(M, A)
```

추가 비용은 **각자 Val2024 예측을 한 번 더 뽑는 것**뿐이고, 그게 위 요청입니다.

**09.11 코드 검증에서 "가중치가 어디서 나왔는가"에 그 자리에서 답할 수 있어야 합니다.** "검증 연도에서 산출"은 방어되지만 "리더보드에서 역산"은 방어되지 않습니다.
