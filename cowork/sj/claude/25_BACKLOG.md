## A. 준비 완료 — 명령만 치면 되는 것

### A1. `F2` base_margin 재학습  — **보류** (offset/logit 계열, 제출 먼저)

**무엇.** 투수 as-of 성공률을 EB 수축해 `base_margin` 으로 걸고, 모델은 잔차만 학습한다.
피처 구성은 `F1` 과 동일하고 학습 구조만 다르다.

```
base_margin = logit(EB(asof_pitcher_success_rate, K=200)) - logit(리그 사전확률)
```

**왜.** V85 가 잰 투수 수준 잔차 천장이 **+186.75** 로 지금 남은 것 중 제일 크다.
V86 의 사후 보정 방식은 실패했지만(이전 시즌 잔차가 전이 안 됨), base_margin 은
as-of 값이라 당해 시즌 정보를 담고 학습 단계에서 트리 분기 구조를 바꾼다. **미검증.**

**상태.** `v77_single_xgb_screen.py` 에 arm 등록 완료. 컴파일·단위검증 통과
(n=0/NaN → margin 0, n 클수록 크기 증가). **학습만 안 돌렸다.**

```bash
python cowork/sj/feature_campaign_1000/v77_single_xgb_screen.py --stage confirm --arms F1,F2 --folds 2023,2024 --device cuda
```

- GPU 필요, 대략 2~3시간 (F1 confirm 2 fold 기준)
- 판정: `F2 − F1` 이 2023·2024 모두 양수인가. 2024 를 두 배로 본다
- 되면 K=200 외에 100/400 도 훑는다. 안 되면 투수 사전확률 축은 닫는다

### A2. `F2` 를 CatBoost 로

CatBoost 가 2022 제외 평균에서 440.30 대 421.84 로 XGBoost 를 앞선다(V84).
본선은 CatBoost 쪽이다. A1 이 XGBoost 에서 통과하면 `train_final_f1_cat.py` 계열에
같은 base_margin 을 이식한다. **아직 이식 안 함.**

### A3. V87 (투수 추세×신뢰 보정) 을 제출 경로에 올리기  — **보류**

V87 이 두 계열 · 두 fold · 넓은 W 구간을 통과했다 (W=0.20 에서 xgb 최악 +3.54).
그런데 아직 **평가 스크립트 안에만 있고 제출 런타임에 없다.**

- 필요한 것: `f1_base_runtime.py` 에 (추세, 신뢰) 25구간 → (a, b) 룩업을 상수로 박고
  `p' = sigmoid(a·(logit(p) − z0) + b + z0)` 적용
- 룩업은 2019~2024 전체로 한 번 적합해 metadata 에 고정 (행 독립성 유지)
- 6단계 검증 필수 — 특히 구조 불변식(훅 중복) 검사

### A4. V83 세그먼트 offset (XGBoost) 제출 경로  — **보류**

`count + li + outs + base_state` 가산, K=50,000 에서 최악 +11.98.
**단 CatBoost 에서는 최선 기준선 위에서 사라진다.** XGBoost 를 낼 때만 의미가 있다.
A3 와 겹치는 부분이 있는지 먼저 확인할 것 — 둘 다 사후 보정이라 이중 적용 위험.

### C1. fold 2022 오염 확인 ★

| fold | AUC | 학습 시즌 |
|---|---:|---|
| 2022 | **0.5770** | 2019~2021 (3시즌) |
| 2024 | 0.5503 | 2019~2023 (5시즌) |

학습 데이터가 제일 적은 fold 의 AUC 가 제일 높다. 순서가 거꾸로고 Phase-0 천장 0.544 도 넘는다.
지금은 판정에서 빼고 있지만(V84), **왜 그런지 확인하면 검증 fold 를 하나 되찾는다.**

> 지금 신뢰할 수 있는 검증 fold 가 2024 하나뿐이다. 이것이 이번 세션 모든 오판의 뿌리다.

### C2. V87 단독 축은 왜 실패하고 교차만 통과하는가

추세만/신뢰만/변동만/수준만은 전부 한 fold 이상 음수인데 추세×신뢰는 통과한다.

알면 다음 보정 설계를 훨씬 좁힐 수 있다.

## 보류 — 제출 먼저 하고 나중에 적용 (2026-08-18 결정)

**offset / logit 보정 계열은 지금 손대지 않는다.** 근거는 다 남겨뒀으니
제출을 더 해본 뒤 필요할 때 꺼내 쓴다.

| 항목 | 상태 | 측정된 값 |
|---|---|---|
| V87 투수 추세×신뢰 보정 | 검증 완료, **미적용** | W=0.20 에서 xgb 최악 +3.54 / cat 2024 +4.00 |
| V83 세그먼트 offset (count+li+outs+base_state) | 검증 완료, **미적용** | xgb 최악 +11.98. cat 은 최선 기준선 위에서 소멸 |
| `v85_preprocess_screen.py` offset 교체 | **손대지 않음** | 아래 참조 |
| F2 base_margin arm | 등록만, **미실행** | 천장 +186.75 (V85) |

### `v85_preprocess_screen.py` — 고치지 않았다. 다만 알고는 있어야 한다

현재 `forecast_offset(rates, FOLD, window=None, damping=0.25)` = `all_d025` 고정.
CatBoost 스크립트인데 CatBoost 최선 전역은 `last3_d075` 다 (V84, fold2024 796.73 vs 820.23).

이미 저장된 10개 arm 의 `.npy` 를 다시 매겨보니 (`v88_prep_rerank.py`, GPU 불필요):

| arm | 예측 오프셋 | Δ all_d025 (현행) | Δ centered |
|---|---:|---:|---:|
| id_frequency | +0.0083 | **+14.26** | +7.94 |
| **temporal_cyclic** | **+0.0120** | **−13.00** | **+4.75** |
| rate_geometry | +0.0093 | +2.75 | +1.67 |
| rate_multiscale | +0.0091 | +3.01 | +0.74 |
| ordinal_numeric | +0.0086 | −2.79 | −7.59 |
| drop_ids | +0.0086 | −52.07 | −57.06 |

- **`temporal_cyclic` 이 7칸 움직인다.** 현행 기준 하위권 탈락인데 오프셋을 빼면 2위다.
  그 arm 의 예측 평균 오프셋이 +0.0120 으로 제일 큰데 all_d025 가 −0.00824 밖에
  안 밀어줘서 생긴 착시다. **신호는 있는데 버려질 뻔했다.**
- `id_frequency` 는 세 기준 모두 1위로 견고. 다만 +16.15 중 절반이 평균 정렬 이득이다.
- 현행 대 최선 기준 순위 상관 **0.700**.

**나중에 적용할 때 할 일** (지금은 하지 않는다)
1. `OFFSET_SPEC = (3, 0.75)` 로 교체 — 계열마다 다르므로 상수로 빼둘 것
2. `bss_centered` 기록 + 그 값으로 정렬
3. docstring 의 "2022/2023/2024 full confirm" → "2023·2024" (2022 는 역신호)
4. `temporal_cyclic` 을 재평가 대상에 다시 올릴 것

> **screen 이 fold 2024 단독인 것 자체는 맞다** — 유일하게 신뢰할 수 있는 fold 다.
