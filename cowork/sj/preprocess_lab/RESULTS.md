## 3. 여기서 읽을 것 넷

### ㄱ. 단독으로 거르면 안 된다 ★

`trackman_quality` 는 **단독 −3.11 로 기각인데 최상위 조합 다섯 개 전부에 들어 있다.**
`context_robust` 도 단독 +0.77(잡음 수준)인데 `id_frequency` 와 함께면 +12.87 이다.

단일 스크리닝만 돌리고 끝내면 이 둘을 버린다. **조합 탐색이 필요한 이유다.**

### ㄴ. 다 켜면 나빠진다

```
id_frequency 단독          +7.94
최고 조합 (3개)           +16.52
all_additive  (8개 전부)   +3.27
all_compact  (12개 전부)   +2.78
```

`all_compact` 는 `id_frequency` 를 **포함하는데도** 단독보다 5점 낮다. 최적은 부분집합이다.

### ㄷ. 제거는 전부 크게 나쁘다

ID −57.06, 성분 −25.95, TrackMan −5.71.
**ID 는 버리면 안 되고 빈도로 바꿔 넣어야 한다** — 같은 열을 두고 방식만 바꿨는데 65점 차이다.
축소(compact)도 전부 손해다 (TrackMan −6.98, 성분 −8.05). "열이 많아 과적합" 직관은 이 데이터에서 틀렸다.

### ㄹ. `raw` 로 골랐으면 `temporal_cyclic` 을 버렸다

raw −17.18 vs centered +4.75. 예측 평균 오프셋이 +0.0120 으로 전 arm 중 가장 큰 탓이다.
그런데 그 arm 은 **최고 조합의 구성원**이다. 반대로 `id_frequency` 는 +16.15 중 절반이 평균 정렬 이득이다.

## 4. 투수별 반응성 (신규 변환)

"이 투수는 어떤 조건에서 자기 평균보다 무너지는가" 를 계층 차감으로 만든다.
`transforms/pitcher_reactivity.py`.

```
split(투수, 조건) = EB(투수, 조건) − EB(투수)
```

### 이미 있는 축과 겹치지 않는다

| 축 | 상태 |
|---|---|
| 타자 손 | **이미 프로덕션** `EB(투수, 타자손)` — 기여 **+13.75** (전체 1위) |
| 볼카운트 | **이미 프로덕션** `EB(투수, 타자손, 카운트) − EB(투수, 타자손)` — **+8.44** |
| 이닝 | 이미 프로덕션 — +2.98 |
| **시즌 부하** | **미탐색.** 이 변환에서 신규 |
| **경기 중요도** | V33 이 `(투수, 타자손, li)` 로 시도해 **−2.72** 실패. 셀 정의를 굵게 바꿔 재시도 |
| **최근 이탈** | 미탐색 |

### 셀 크기 (학습 시즌, K=300)

| 셀 정의 | 셀 수 | 중앙 n | 한 행 기여 |
|---|---:|---:|---:|
| (투수) | 711 | 807 | 0.090% |
| (투수, 타자손) ← 현행 기준 | 1,413 | 393 | 0.144% |
| **(투수, 부하5군)** | 2,003 | **400** | **0.143%** |
| (투수, li 5군) | 3,198 | 130 | 0.233% |
| (투수, 타자손, li) ← V33 방식 | 6,099 | 72 | 0.269% |

전부 1% 미만이라 자기 라벨 누수 관문 통과 ([METHOD.md §7](METHOD.md)).
부하 축은 현행 타자손과 셀 크기가 동급이다.

### 데이터 제약

**등판 내 투구 수가 데이터에 없다.** 유도하려면 test 행끼리 묶어 세야 하는데 행 독립성 위반이다.
그래서 "부하" 는 시즌 누적 `asof_pitcher_n` 으로 잡았다.

### 결과 — 기각

| 조합 | Δ centered | 반응성 없는 같은 조합 대비 |
|---|---:|---:|
| `pitcher_reactivity` 단독 | −1.39 | (기준선 대비) |
| `id_frequency + pitcher_reactivity` | +5.56 | **−2.38** (`id_frequency` 단독 +7.94) |
| `id_frequency + pitcher_reactivity + temporal_cyclic + trackman_quality` | +12.45 | **−4.07** (최고 조합 +16.52) |

**세 경우 모두 손해다.** 단독은 잡음 범위(sd 1.37) 안이고, 조합에 넣으면 일관되게 깎는다.
`trackman_quality` 처럼 "단독은 나쁜데 조합에서 사는" 유형도 아니었다.

**해석.** 네 축 중 셋(타자손·볼카운트·이닝)은 이미 성분 파이프라인의 계층 차감으로 들어가 있고,
그 정보가 `sx_cf_*` 열을 통해 이 모델에도 이미 전달된다. 남은 두 축(부하·중요도)은
V33 이 `(투수, 타자손, li)` 로 이미 −2.72 를 냈던 것과 같은 결론이다.
**셀을 굵게(130행 → 400행) 바꿔도 살아나지 않았다.**

> 축이 아니라 구조를 바꿔야 한다는 V33 의 결론이 다시 확인됐다.
> 다만 `pitcher_reactivity.py` 는 랩 기여 규약의 첫 실사용례로 남겨둔다 —
> 계층 차감 테이블을 만드는 변환을 어떻게 쓰는지 보여준다.
