## ⚠️ 착수 전에 반드시 정리할 것 — 결합 가중치의 출처

팀통합 문서 §5-3은 최적 가중치를 이렇게 구한다.

```text
A = (BSS × U + V) / 2     ← BSS는 각자의 Public 점수
w* = M⁻¹A                  ← M은 예측 간 공분산
```

**이 방식 그대로는 규정 위반 소지가 크다.** 두 군데가 걸린다.

| 항목 | 문제 | 근거 |
| --- | --- | --- |
| `A`를 **리더보드 점수에서 역산** | Public BSS는 평가 데이터의 실제 정답으로 계산된 값이다. 이걸로 가중치를 맞추면 평가 데이터 라벨에 fitting하는 것 | [`RULES.md`](RULES.md) §2 · §9 · §10-A |
| `M`을 **test 예측으로 계산** | test 행을 가로지르는 공분산 = 평가 데이터 분포 이용 | `RULES.md` §2 |

가중치가 전 행에 동일하게 적용되는 상수라는 점은 **면책이 되지 않는다.** offset에서 이미 정리한 논리와 같다 — 전 행 동일 적용은 필요조건일 뿐이고, 문제는 값의 출처다 (`RULES.md` §2 「상수 오프셋의 허용 조건」).

### 대안 — 수식은 그대로, 출처만 바꾼다

`A`와 `M`을 **홀드아웃 검증 연도(2024)에서 실제 라벨로** 계산한다. 닫힌 형태 `w* = M⁻¹A`는 동일하고, 리더보드는 한 번도 경유하지 않는다.

```python
# 각자 Val2024 예측(공통 split, 같은 row 순서)을 모은다
D = np.column_stack([p_i - r for p_i in val_preds])   # r = 학습 데이터 기반 상수
M = D.T @ D / len(D)                                   # 검증 예측만으로 계산
A = D.T @ (y_val - r) / len(D)                         # 검증 정답 사용
w = np.linalg.solve(M, A)
```

추가로 드는 비용은 **각자 공통 Val2024 split에서 예측을 한 번 더 뽑는 것**뿐이다. 대신 09.11 코드 검증에서 "가중치가 어디서 나왔는가"에 그 자리에서 답할 수 있다.

리더보드 점수를 참조한 결합은 09.11 검증에서 방어 불가다. **"검증 연도에서 산출"은 방어되지만 "리더보드에서 역산"은 방어되지 않는다.**

> 이 판단을 팀에 먼저 공유하고 합의할 것. 1순위 작업의 전제가 바뀌는 문제다.

## 우선순위

### 1. 팀 모델 결합 — 가장 큰 기회

1. 각자 **공통 Val2024 split**에서 예측 CSV를 뽑아 공유 (같은 `row_id` 순서)
2. 상관 행렬 계산 → 결합 이득 확인. 0.85 이하면 크고, 0.9 이상이면 작다
3. `w* = M⁻¹A`로 가중치 산출 + 예상 점수
4. 견고성 확인 — `V` ±15%, 가중치 ±0.1을 흔들어 평평한지 본다
5. 통합 `script.py` 제작 → **한 번만 제출**

주의:
- **`target_rate`를 먼저 통일한다.** 승주 0.4792, 찬우 0.47353. 안 맞추면 보정이 중복된다. 통일값도 학습 데이터에서 결정해야 한다.
- 약한 라인을 억지로 빼지 않는다. `w*`가 알아서 작은 가중치를 준다. 상관이 낮으면 797점 라인도 기여한다.
- **추론 시간.** 찬우 2계열 51초, 승주 시스템은 더 무겁다. 결합하면 배가된다. 245,789행 / 10분 제한.
- 여러 조합을 다 제출하지 않는다. 1일 5회 제한이고, 결합은 한 번이면 검증된다.

## 검증 프로토콜 (팀 통일안)

1. **노이즈를 먼저 잰다** — 같은 설정으로 시드만 바꿔 5~8회. 그 산포가 측정 한계다. (3시드로 판단했다가 8시드에서 뒤집힌 사례 2건)
2. **최소 2개 연도, 가능하면 3개** — 2022(정상) + 2023(레짐 변화) + 2024(직전). **2024만 보면 안 된다.**
3. **한 번에 하나씩만 바꾼다** — 6개를 묶어 냈다가 실패해 원인 분리가 불가능해진 사례가 있다.
4. **채택 기준** — 새 피처는 노이즈의 1.5배 이상 + 2개 연도 일관. 앙상블/배깅/캘리브레이션은 노이즈 이상이면 채택.
5. **검증 이득은 할인해서 기대한다** — 피처 40%, 구조 변경 90% 전이.

## 엔지니어링 체크리스트 — 실제로 터졌던 것

- **sklearn/joblib pickle 금지.** 로컬 1.6.1 vs 서버 1.8.0 불일치로 로드 실패

- catboost 1.2.8은 numpy<2.0 필요
- zip 경로는 forward-slash 강제 — Windows 백슬래시는 `extractall()`이 보정 안 함
- LightGBM은 컬럼 **순서**까지 고정. 새 피처는 항상 맨 끝에
- 추론 시간 측정 — 결합하면 배가된다
- 5행 샘플로 end-to-end 실행
