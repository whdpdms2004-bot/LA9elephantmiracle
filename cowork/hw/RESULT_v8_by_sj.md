**배깅이 잘 작동합니다.** CatBoost 개별 평균 608.11 → 앙상블 627.68 (**+19.57**), LightGBM 622.19 → 631.08 (**+8.89**). 그리고 50:50 결합이 두 계열 각각보다 높습니다(635.88 > 631.08 > 627.68). 팀통합 §2-2 예나 결론(계열 단위 가중)이 그대로 재현됐습니다.

## ★ 발견 1 — 예측 평균이 1.04%p 높습니다. 이것만으로 43 BSS입니다

```
2024 실제 평균   0.486105
v8 예측 평균     0.496470
편향             +0.010365  (+1.037%p)

벌점 = 100000 × 0.010365² / [0.486105 × 0.513895] = 43.01 BSS
```

팀통합 §2-1의 `Score 손실 ≈ 401,000 × 오차²` 공식과 일치합니다.

**레벨 보정만으로 635.88 → 약 679가 됩니다.** 새 피처나 튜닝 없이, 예측 평균을 맞추는 것만으로요.

주의할 점은 팀통합 §2-1이 지적한 조건입니다.

> `season`을 피처로 남겨두면 트리가 마지막 연도 구간으로 예측 수준을 자동으로 맞춰준다. 빼면 347 → −48로 폭락한다.

v8은 `season`을 쓰고 있는데도 +1.04%p가 남았습니다. 즉 **`season`만으로는 부족하고 추가 보정 여지가 실제로 있습니다.** 다만 정희원님 라인이 과거 "로짓 절편 보정 + shrinkage"로 2022/2023/2024 전부 악화한 이력이 있으니, 외삽 규칙을 **감쇠(λ≈0.33~0.5)** 로 바꿔 재시도하는 걸 권합니다 (찬우 백테스트: 3년 선형 .4877 vs 감쇠 .4815~.4855, 실제 .4861).

참고로 sj 라인에서 감쇠 외삽을 격리 측정했을 때는 효과가 없었습니다(선형 대비 +0.4 이내). 다만 그건 **이미 보정된 base 위**에서였고, v8처럼 +1.04%p가 남아 있는 상태에서는 얘기가 다릅니다.

## ★ 발견 2 — −14.66을 "하이퍼파라미터가 나빠졌다"로 읽으면 안 됩니다

v8은 두 가지를 **동시에** 바꿨습니다.

| | v7 | v8 |
|---|---|---|
| 하이퍼파라미터 | 기존 | 신규 튜닝 |
| CatBoost 시드 | 20 (16개 완료) | **5** |
| LightGBM 시드 | 20 | **10** |

**시드 축소만으로도 BSS가 내려갑니다.** 위에서 본 대로 CatBoost 5시드 배깅이 이미 +19.57을 만드는데, 20시드였으면 더 컸을 값입니다. −14.66 중 얼마가 시드 탓이고 얼마가 파라미터 탓인지 지금 데이터로는 분리가 안 됩니다.

그래서 **하이퍼파라미터를 하나도 안 건드리고 CatBoost 시드만 5→20으로 늘려** 다시 측정하고 있습니다.

→ [`extra_seeds_by_sj.py`](extra_seeds_by_sj.py) · 결과는 `submission_v8/extra_seeds_by_sj.json`

시드 5/8/10/12/15/20 각각의 앙상블 BSS 곡선이 나오면, 시드를 되돌렸을 때 anchor에 얼마나 근접하는지가 바로 보입니다. **곡선이 650 근처로 수렴하면 파라미터는 문제가 없고 시드 축소가 원인**입니다.

## PHASE 2 — production 산출물

`fit = season < 2025` (train.csv 전체)로 재학습해 저장했습니다.

```
submission_v8/
├── model/
│   ├── cat_seed2026~2030.cbm      5개  (2.7~3.9MB)
│   ├── lgb_seed2026~2035.txt     10개  (1.5~2.1MB)

│   └── medians.json
├── phase1_progress.jsonl          체크포인트 15개 기록

```

총 **33MB**. 네이티브 포맷(`.cbm` / `.txt`)이라 팀통합 §1-7의 pickle 금지 규칙을 지킵니다.

`best_iteration`은 Phase 1에서 확보한 값을 그대로 썼습니다 (CatBoost 236~342, LightGBM 206~290).

### ⚠️ 가중치 파일은 깃에 못 올립니다 — 대신 더 좋은 방법이 있습니다

`.gitignore`가 `*.cbm`(32행)과 `lgb_*.txt`(38행)를 막습니다. 저장소 정책이 *"모델 가중치·제출 ZIP도 커밋하지 않는다. 가중치 대신 그걸 만드는 학습 코드를 올린다"*(README)라서 제가 임의로 예외를 넣지 않았습니다.

**그런데 비싼 건 가중치가 아니라 `phase1_progress.jsonl`입니다.**

| 단계 | 소요 (24코어) | 내용 |
|---|---:|---|
| **Phase 1** | **1,135초 (19분)** | early stopping으로 `best_iteration` 탐색 ← **비싼 쪽** |
| Phase 2 | 646초 (11분) | 고정 iteration으로 production 재학습 |

`phase1_progress.jsonl`(15개 멤버의 `best_iter` 기록)은 **커밋했습니다.** 스크립트 체크포인트 설계상 이 파일이 있으면 —

```
git pull
cd cowork/hw
python train_best_model_v8.py     # Phase 1 전체 건너뜀, Phase 2만 실행
```

**Phase 1이 통째로 스킵되고 Phase 2만 돕니다.** 12코어 노트북이면 20~25분 예상입니다. 4시간+ → 25분.

같이 커밋한 것: `phase1_progress.jsonl` · `model/feature_cols.json` · `model/medians.json` · `requirements.txt`

가중치 파일이 바로 필요하시면 말씀해주세요. 33MB라 다른 경로로 전달하거나, 팀 합의로 `.gitignore` 예외를 넣으면 됩니다.
