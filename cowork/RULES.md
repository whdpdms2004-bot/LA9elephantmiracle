## 2. ★ 추론 독립성 원칙 — 가장 중요

### 원문

> "평가 데이터(test.csv)의 각 행은 하나의 독립적인 예측 대상입니다."
>
> "평가 데이터의 다른 행이나 전체 평가 데이터의 분포를 이용해 특정 행의 예측값을 보정하거나 생성하는 방식은 정상적인 추론 절차로 인정되지 않습니다."

### 8/13 재공지 (`talkboard/417123`) — 위반 사례 명시

제목: **평가 데이터 독립 예측 원칙 위반 사례 관련 재안내**

금지로 열거된 행위:

- test.csv의 다른 행을 이용한 **누적 통계** 생성
- test 행들로부터 **rolling / lag 피처** 생성
- test 데이터의 **분포·평균·순위**를 이용한 예측값 조정
- test 행을 가로질러 **선수·팀·월·경기 단위 집계**

판정 기준:

> **단일 행에 대한 예측은, 그 행이 단독으로 존재하든 전체 test 데이터셋 안에 있든 동일해야 한다.**

또한 생성형 AI 사용은 허용되지만, 제출 코드가 규정을 준수하는지에 대한 **책임은 참가자에게 있다**고 명시했다.

### 실무 판정 테스트

```
predict(row_i alone)  ==  predict(full_test)[i]
```

이게 성립하지 않는 코드는 전부 위반이다. 구체적으로:

- ❌ `test.groupby('pitcher_id')[...].transform(...)`
- ❌ `test.sort_values('date').groupby(...).cumsum()` / `.shift()` / `.rolling()`
- ❌ `pred = (pred - pred.mean()) / pred.std() * a + b`
- ❌ `pred = pred + (target_rate - pred.mean())`
- ❌ test 예측 분포에 맞춘 rank/quantile 매핑
- ✅ `model/`에 미리 저장된 **학습 데이터 기반** lookup 테이블을 `pitcher_id`로 merge
- ✅ 같은 행에 대한 여러 seed/모델 예측의 평균 (`np.mean(..., axis=0)`)
- ✅ 학습 데이터에서 사전 결정된 **상수** 오프셋 (모든 행에 동일 적용)

## 4. 리더보드 제출

| 항목 | 값 |
|---|---|
| 1일 최대 제출 | **5회** |
| Public Score | 전체 테스트 데이터 **100%** |
| Private Score | **대회 종료 시점의 Public Score와 동일** |
| 평가 지표 | Brier Skill Score |

```
Score = max(0, 100000 × (1 − Brier Score / 평균 제구율 Brier Score))
Brier Score          = mean((p_i − y_i)²)
평균 제구율 Brier Score = r × (1 − r)      # r = 전체 평가 데이터 평균 제구 성공률
```

- Public/Private 분할이 **없다.** shake-up도 없고, 최종 제출 2개를 고르는 절차도 없다. 종료 시점의 Public이 그대로 최종 점수다.
- 수료 기준: Phase 2에서 **549.51 이상** (평가 탭 기재 — 최종 확인 권장)
- 제출 횟수 차감 규칙:
  - **설치 오류** (구조 불일치, `requirements.txt` 설치 실패/시간 초과) → **차감 없음**
  - **제출 오류** (`script.py` 런타임 에러, `submission.csv` 미생성, 추론 시간 초과) → **차감됨**

## 5. `submit.zip` 규격

```
submit.zip
├── model/              # 학습된 가중치·lookup 전부
├── script.py           # 추론 전용, 파일명 정확히 일치
└── requirements.txt
```

**"다음 구조를 엄격히 준수해야 합니다"** — 최상위에 다른 폴더/파일을 두면 설치 오류.

### `script.py` 요건

- 파일명 정확히 `script.py` (`Script.py`, `SCRIPT.PY` 불가)
- **추론 전용.** 학습 루프, 전처리 fit, 가중치 업데이트 코드 포함 금지
- 입력: `data/` 에서 읽기
- 출력: **`output/submission.csv`** 반드시 생성
- 경로: 상대 경로 또는 `Path(__file__).resolve().parent` 기준. 하드코딩된 절대 경로 금지
- 파일명에 공백·한글 금지

### `requirements.txt`

- 버전 고정 권장 (`xgboost==3.1.1` 형태)
- 평가 서버 기본 설치 패키지는 **가급적 포함하지 말 것** — 이미 버전 호환이 맞춰져 있음
- 오프라인 설치 불가능한 패키지 금지

### `model/`

- 필요한 모든 파일(가중치, 토크나이저, 설정, lookup) 사전 저장
- 온라인 다운로드 의존 금지, 빈 디렉터리 금지

## 10. 우리 프로젝트 리스크 점검

### A. ★ `submit_022` 제출 후 2025 성공률 역산 — **하면 안 된다**

`submit_41.md` §12-1 / `status.md` 「다음 순서」에 있는 계획:

> "`submit_022.zip` 제출 — 두 Public 점수의 차이가 곧 2025 레벨 가정의 직접 검증이 되고, 여기서 2025 실제 성공률의 방향을 역산할 수 있다."

**절반은 괜찮고 절반은 위반이다.**

- ✅ **offset 유무 ablation을 제출해 점수를 재는 것** 자체는 정상적인 실험이다.
- ❌ **거기서 역산한 2025 실제 성공률로 `season_logit_offset`을 재조정하는 것**은 위반이다. 리더보드를 경유했을 뿐 결과적으로 "전체 평가 데이터의 평균을 이용해 예측값을 보정"한 것이 되고, 이건 8/13 재공지가 명시적으로 열거한 금지 행위다.
- 09.11 코드 검증에서 "0.4792라는 값이 어디서 나왔는가"를 설명해야 한다. **"2019~2024 추세 외삽"은 방어되지만 "리더보드에서 역산"은 방어되지 않는다.**

현재 `submit_023`의 offset은 학습 데이터(2019~2024)에서 사전 결정된 상수이고 모든 행에 동일하게 적용되므로 **행 독립 원칙을 만족한다.** `submit_41.md` §8 「원칙」에 그 근거가 이미 문서화돼 있다 — 이 문서를 그대로 코드 검증 근거로 제출하면 된다.

**권고: offset은 현재 값에 동결. 리더보드 피드백으로 재조정하지 않는다.**

### B. `script.py`의 `distribution_match` 분기 — 사문화됐지만 **삭제 권장**

`script.py:683-702`에 다음 코드가 있다.

```python
if outer.get("distribution_match"):
    if mode == "probability_mean_std":
        source_std = max(float(large_prediction.std()), 1e-8)
        insight_prediction = (
            (large_prediction - float(large_prediction.mean()))
            * (float(anchor_prediction.std()) / source_std)
            + float(anchor_prediction.mean())
        )
```

이건 **test 배치 전체의 mean/std로 예측을 재척도하는 코드**다. 행 독립 원칙 정면 위반이며, 단일 행 추론 시 `std()=0`이 되어 결과가 완전히 달라진다.

- **현재 실행되지 않는다.** `submit_023`의 `metadata.json`에는 `distribution_match` 키가 없어 `else` 분기로 빠진다 (확인 완료).
- 그러나 09.11 코드 검증에서 사람이 `script.py`를 읽는다. **검증자가 이 블록을 먼저 발견하면 설명 부담이 크다.**
- **권고: 다음 제출 패키지에서 이 분기를 통째로 제거.** 활성 경로가 아니므로 예측값은 비트 단위로 동일하게 유지된다.
